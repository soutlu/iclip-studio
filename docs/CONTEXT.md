# iclip-agent 领域锚点

本文定义 Productor 视频创作产品的领域上下文、术语、不变量与禁止逻辑，两端共用。命令与门禁见 [../AGENTS.md](../AGENTS.md)；机制见 [architecture.md](architecture.md)；跨端约定见 [../contract/conventions.md](../contract/conventions.md)；决策见 [adr/](adr/)。

## 上下文

- **产品**：Productor 是 AI 视频创作产品。用户与 AI agent 对话推进创作：从参考素材拆解，到镜头 prompt 表，再到镜头帧与媒体生成。
- **系统**：`web/` 产品前端 + `server/` 后端。Postgres 持有本系统的业务事实与运行状态，对象存储持有媒体字节。企业身份与部门资料来自 企业 SSO / PMS，PDM 款目录来自外部只读库，爆款数据是随迁移灌入的快照，模型与媒体生成由外部服务提供。
- **两端分工**：后端定义业务接口，前端消费合同并实现产品交互；双方遵守本文的领域语义。接口形状以 [../contract/openapi.json](../contract/openapi.json) 为准，前端边界见 [../web/AGENTS.md](../web/AGENTS.md)。

## 术语

**主体（Principal）**：
请求或运行使用的可信身份，区分用户与 API key，包含归属用户、API key 身份（如有）、生效权限集和属主账号的用户名。由宿主建立，下游只消费它。

**API Key**：
归属某个用户的长期机器凭证，服务端只存哈希与展示前缀。有效权限是显式授予集，签发时不得超出签发者当下权限；签发需 `api_keys:issue`，预置角色中仅 root 持有。传输见 [跨端认证约定](../contract/conventions.md#2-双主体认证-dual-principals)。
持 `users:act_as` 的 key 可**替人办事**：写入口的请求体里给了 `user_name`，那次请求就以那个人为主体，属主、创建者、认领人都记他；系统里还没有这个人时先建一个只有用户名的占位账号，本人日后 SSO 登录按用户名认领。权限仍是 key 自己的显式授予集，审计标识记「那个人#key 名」，能替任何人写的 key 也能读任何人的记录。没有这个权限的 key 一切照旧，`user_name` 只是发往上游的标签。

**角色（Role）**：
权限集合的命名快捷方式。用户有效权限 = 所分配角色的权限并集 ∪ 直接授权。权限词汇与预置角色以 [rbac.py](../server/src/iclip/domains/identity/rbac.py) 为准。

**双主体（Dual Principal）**：
同一套产品能力对浏览器用户与机器调用方开放。两者使用同一 Principal 类型与权限词汇，认证传输见 [跨端认证约定](../contract/conventions.md#2-双主体认证-dual-principals)。

**运行目标（Run Target）**：
对话绑定的顶层 Agent，由声明式配置定义模型、提示词、能力与下属。目标 ID 是引用身份；客户端只能选择已声明目标，不能自行指定模型、provider 或提示词。

**对话（Conversation）**：
用户界面上的一个聊天窗口；挂到需求单下时代表一次创作尝试。有属主和名字，属主可改名、删除。一段对话可有多次运行，工作区与对话素材按对话隔离；删除只是标记，运行记录、工作区与素材台账都保留，对话 ID 不可重新分配。普通用户只看自己的对话，删掉的对自己也不再可见；持 `users:manage` 的治理者可复盘全部对话，含已删的墓碑，写入仍限属主；墓碑上对话自身的操作（改名、换归属、发消息、改工作区文件）对谁都关着，生成任务的对话归属只是标签、不校验对话。
它可以从**某一轮分叉**出一段新的：副本归分叉的人所有，带着源对话截到那一轮的历史、当下的工作区与素材；出片记录不拷，副本按血缘**继承**。源对话一个字节都不改。谁读得到就分得动，所以治理者连墓碑也能分叉。副本记着来源与分叉点，不进审计报表；它拿到的是分叉那一刻的那一份文件与出片，不是当年那一份，继承来的轮也不能重新生成。
它带两处归属，各自独立、都可为空、都可随时更换：所属需求单（至多一张），所属合集（至多一个）；归属所指的行被删掉时只把对话上那一列置空。分叉不继承这两处归属。
它此刻**在忙什么**是四件互不蕴含的事实：有轮次正在跑（busy），有没有卡在等人点头（approval / question，两者都有时审批优先），最近一轮的结局（completed / failed / aborted），以及这段对话下有没有还没跑完的视频记录（出片、编辑段、合成都算；none / queued / running，有一条已开始提交就是 running）。**等审批的时候仍然是 busy；视频在跑不算 busy**，它是生成任务的事，不是轮次的事。
它另有一件与「在忙什么」不同层的事实：**属主标没标收尾**。这是人的判断不是引擎推的，机器永不自动标；属主再动手（开跑新一轮、提交出片）就自动抹掉。

**合集（Collection）**：
对话的分组单位，有属主。普通用户只访问自己的合集；治理者可查询、改名和删除全部合集，各操作仍需对应权限。对话可见性独立于所在合集。

**Agent 运行（Agent Run）**：
一次 agent 执行的持久事实，包含运行血缘、逐步事件、消息历史与工具副作用状态。一轮用户消息可因审批或恢复经历多次运行；轮与运行不是一一对应。

**运行依赖（Run Deps）**：
运行所携带的可信主体、对话归属与归属标签 `user_name`。主体在开跑时按消息记录的属主重建：是一个用户主体，权限取自他账号当下的角色，不带发消息那把 key 的身份与权限；替人办事的消息，属主就是 `user_name` 指名的人。每次 run 开始后主体与权限保持不变，下属运行继承它。工具的授权与审计只认该主体。归属标签是这次运行替谁跑，由发消息的调用方给出、随消息记录持久化，工具把它发给上游落表对账；它本身不参与授权。持 `users:act_as` 的 key 带它进来时，入口已按它换好了主体（见 API Key），下游仍然只消费主体，不再看标签。

**对话素材（Conversation Material）**：
该对话素材台账中的图片或视频，以完整 URL 字符串精确识别，并记录媒体种类。用户以附件提交的地址和镜头素材工具产出的地址进入台账；正文里写出的地址、模型生成的地址与读文件时见到的地址不会自动登记。受素材约束的工具要求地址已在本对话台账中且种类匹配，历史压缩不改变这一资格。台账只约束来源，出网安全仍由获取素材的边界负责。机制见 [architecture.md](architecture.md)。

**模型上下文（Model Context）**：
一次实际发送给模型的指令与消息窗口，区别于持久化的完整历史。压缩在完整历史中增加摘要边界，后续请求使用摘要与边界后的消息；原消息仍保留，Transcript 不因压缩丢轮。摘要是二手信息，关键事实需回到原始来源核对。机制与配置见 [architecture.md](architecture.md)。

**Transcript**：
一段对话给人看的记录：轮（一条用户消息引发的全部运行）→ 步（一次模型响应）→ 块（正文、思考、工具卡等）。它是运行事实的投影，不能反向充当运行事实源。协议与断线恢复见 [跨端约定](../contract/conventions.md#5-agent-对话-transcript)。

**对话用量（Conversation Usage）**：
一段对话在每个模型上累计的模型响应次数与四类 token（普通输入、缓存读、缓存写、输出），模型每答一次累加一行，不逐次落行。归属对话取运行依赖里继承的对话 id，子代理的用量记到同一段对话；需求单粒度沿对话当下挂的需求单汇总。只覆盖 Agent 运行里的模型请求，标题生成、压缩摘要与视频理解不计。

**镜头组（Shot Group）**：
分镜是一段对话当前的出片方案（工作区里的 `video_shot.json`），由镜头组按顺序组成。镜头组不另设 id，身份就是调用方给的**镜号**（镜头组编号，从 1 起，与分镜文件的 `shots[].index` 同一套）；重新切分后，同一编号下的新旧记录连着算。镜号是视频记录上的一列：出片由调用方在请求里给，可以不给；编辑段与合成抄原作的镜号。`metadata` 里的键不算镜号；图片没有镜号，分镜页用 `metadata` 自己记它属于哪一镜哪一帧。镜头组之下，**镜头**是时间线上的一段，**镜头帧**是镜头组里的第 N 张图，正文里用 `@ImageN` 引用。镜头帧指向一张**图片**：图片是生成、切出或上传的图，放进镜头组才叫镜头帧；帧图编辑以底图那一行为锚，不以第几格为锚。镜头组也是**版本组**：一段对话读得到的成片（自己的加继承来的）按镜号分组，组内按完成时刻编 V1、V2……，重出与合成都往后排，读时现算；没有镜号的出片各自一组，同原作的合成跟着它。

**审计口径（Audit Metrics）**：
治理者看产量、成功率、耗时与模型消耗的一组固定定义，全体、人、需求单、时段、对话各层同一形状。分叉出来的副本一律不计入。视频只算有镜号且挂着对话的出片，编辑段与合成不算；需求单沿对话当下挂的需求单归属；视频归属主（按属主的用户名），对话归最近一轮运行的人，没跑过就归最近一条视频的属主。**成片件数**：有成片的需求单各算一件，没挂需求单却有成片的对话各算一件。**镜**的身份是（对话，镜号），生成次数含失败与在途的尝试；只出了一条且成了算**一次通过**，成了又重出的不算。至少成了一条的镜是**出片镜**；有人下载过的镜是**有效镜**（看 `video.downloaded` 埋点事件），下载的是合成时按原作算到原作所在的镜，下几次都只算一镜；**有效率** = 有效镜 ÷ 出片镜。**出片次数分布**按镜的生成次数分档统计（只给全体一档）：停下就算收工，不看终态，所以累计通过曲线必然收在 100%。**运行次数**是 agent 运行的条数，归发起人，含已删对话的。**交付周期**：一段对话从首次运行（没有运行就从对话创建）到最后一条成片。异常是对这些数字的越界判断，门槛见合同。

**生成任务（Generation Job）**：
一次操作的持久事实：调了模型，或产出了本系统持有字节的媒体，就记一行。记着属主与 API key 身份、发给执行方的输入 `request`、状态和结果，可归档到对话与需求单；视频另记镜号（见「镜头组」）。**作者**就是属主的用户名；`request` 里的 `user_name` 只作发给上游对账的输入，不用来归人（替人办事的钥匙已按它换好属主，见 API Key）。还可带调用方自己的标签 `metadata`：服务端不读不写、原样存取，分镜页用它给图片记镜头组与帧。一行是哪种记录，由种类 `kind`、操作 `operation`（调模型 generate、本地拼接 compose、本地切图 cut、用户上传 upload）与有没有**来源** `source_job_id`（直接基于库里的哪一行）决定：**出片**是没有来源的视频 generate；**编辑段**是在一条成片上改一段、调模型的视频 generate，来源是那条成片，并记改的区间；**合成**是把编辑段夹回它的基底、本地拼接出来的视频 compose，来源是那条编辑段。**帧图编辑**是基于一张底图、调模型的图片 generate，来源是底图那一行，底图不在库里时记外部地址 `source_url`，两者恰好一个；**切图**是从一张宫格上切出来的图片 cut，来源是那张宫格；**上传**是用户传进来的图片或视频 upload，没有来源、不挂对话。切图与上传创建即完成，没有 `request`。图片的来历顺着来源往上走，只剩外部地址的是外部起点。编辑段与合成另带**原作** `root_job_id`，指最初那条出片，不管基于哪一版，链因此只有一层；来源与原作可以是所在对话自己的，也可以是它继承的。编辑段与合成不计审计口径。**成片**是一条完整、可播放的视频：已完成的出片或合成；编辑段不是成片。编辑时切给模型看的参考片段不落行。生成任务的业务状态与 provider 的原始状态分别记录；排队与提交机制见 [architecture.md](architecture.md)。

**继承（Inherited Records）**：
分叉副本与祖先对话出片记录之间的只读关系。副本继承的记录：沿分叉来源往上的每个祖先名下，已完成、且完成时刻不晚于「这条链上它的下一级对话的建立时刻」的记录；边界逐跳算，不是一律截在副本建立那一刻，两个时刻都是数据库时钟。继承是读得到，不是归属：记录所在的对话与属主都不变；可以下载、可以当基底去剪、可以当帧图编辑的底图，不能重出。在副本里剪出的编辑段与合成是副本自己的记录，来源可以是继承来的那条，原作指祖先对话里那条出片。读得到副本的人按对话列副本的记录时连继承的一起看到，读不到就只按属主；单条读仍只按属主。祖先删成墓碑不影响继承。资料库装卡用的也是这一集合，不看读者（见「资料库」）。

**生成结果（Generation Output）**：
一次成功生成对外给出的地址。图片是转存成本系统的公开对象后才算数（网关给的是会过期的签名地址），转存不成功这次生成就是失败，不留网关的地址。视频存上游发布好的两个稳定地址（原片与水印版），缺任一份这次生成就是失败。

**资料库（Library）**：
全站通过本系统成功生成的视频连同出片那一刻的脚本，给再创作复用的只读视图；与 PDM 款目录无关。收录成片（已完成、有地址的出片或合成），不看删除标记：卡所在的对话或它的祖先删了，卡都照旧。一张卡是一段对话的分镜：内容是这段对话按「继承」读得到的全部成片，按镜头组分组、组内编版本（见「镜头组」）；不挂对话（对话不存在也算）的出片一条一张卡，同原作的合成跟着它。对话自己至少有一条成片才有卡，在继承来的出片上剪出的合成算自己的；卡面是自己最新的那条，卡面的完成时刻是列表排序与时间筛选的依据。同一条成片出现在源对话的卡和每个有自己成片的副本的卡里，不去重、不标注。作者与每一版的归属人都是属主的用户名：卡的作者是对话属主，不挂对话的是出片属主；每一版是那条成片的属主，不看请求里的 `user_name`。脚本取自请求：带结构化镜头组的直接用，只有正文的按拼装规则反拆，拆不出来就是纯文本，不猜结构；合成的脚本与参数沿原作取。持 `generation:read` 的人都看得到全站的片、脚本与对话 id，这是生成记录「只看自己的」之外有意开的读范围（另一处是「继承」：读得到副本就能按对话读它继承的记录）；打不打得开那段对话仍按对话自己的可见性。

**埋点事件（Tracking Event）**：
前端在用户做了某件要记账的事时发来的一条事实，服务端只追加落表。事件名是封闭的表，每个事件名规定必带哪个主语（生成记录或对话），缺了或多带都拒收；发起用户与 API key 取自主体，发生时刻用数据库时钟，身份与时间都不收客户端给的。现有的只有 `video.downloaded`：主语是一条可下载的视频，即成片（有地址的出片或合成），编辑段不算，不看是谁的片；不存在与不合格一样回 `404`，不区分。下载事件不记对话，审计经生成记录推回镜。

**PDM 款目录（Style Directory）**：
款在 PDM 中的品类与品牌归属，来自外部只读库，本系统不维护产品主数据、也不对外提供产品资料查询。只保留编码，供爆款视频按品类与品牌圈选同类款；名称字典留在上游库里，本仓不冻副本。需求单持有调用方确认的商品信息快照，不随上游资料变化而自动更新。

**上传（Upload）**：
本地文件直传进本系统对象存储后得到的一个公开地址。服务端签发直传许可，传完按桶里的对象核对类型与大小，通过后记一条上传记录（见「生成任务」），id 就是签名时发的 `uploadId`，重复确认得到同一条。记录的属主是确认时的主体（替人办事可换成指名的人）；签名者与 key 另随对象元数据存在桶里。与对话素材台账是两件事，上传不自动赋予任何对话使用资格。

**创作需求单（Task）**：
一份记录在案的视频创作要求，创作内容包括视频规格、商品信息、分类参考素材和创作说明，并记录创建者、期限、状态与认领人集合。没有属主，持 `tasks:read` 可见全部；草稿由创建者与治理者管理，下发后按冻结规则修改。可由多人认领，撤回是终态且不抹去认领记录。**对话挂上需求单就是认领**：有人拿它开了一次创作尝试，这张单就从待认领进入进行中，对话属主记为认领人；摘掉对话不抹认领。状态转换、修改权限与冻结字段见 [需求单约定](../contract/conventions.md#8-创作需求单-tasks)。

**爆款视频（Inspiration Video）**：
自家款在平台上表现最好的短视频，随迁移灌入的一次性快照，运行时不从原始视频库刷新。数仓按 WMS 编号记账，入库时已解析成 PDM 款号并冻结品类与品牌，因此查询使用 PDM 款号。一个款自己有爆款视频是少数情况，没有时使用 PDM 款目录中的归属，按同品牌同类目、同类目逐级取替身，匹配层级随结果返回。

## 不变量

每条代码路径都必须遵守。实现偏差应修复，改变以下规则须显式决策。

1. **Postgres 是本系统业务事实与运行状态的唯一持久化事实源。** 进程内存不承载跨 worker 正确性；Transcript 的实时投影与性能缓存不构成第二个事实源。
2. **可信身份只来自宿主建立的 `Principal`。** 同一请求只解析一次凭证；下游不得再次解码凭证或消费客户端身份字段来建立另一份身份。替人办事的换主体只在写入口做一次、只对持 `users:act_as` 的 key 生效，换出来的仍是同一份 `Principal`。HTTP 与 WebSocket 共用身份解析规则，浏览器 WebSocket 还须校验 Origin。
3. **权限集合是唯一授权依据。** 用户与 API key 分别按上文定义计算权限；过期、吊销或属主停用的 key 必须被拒绝，不能退回属主的用户权限。
4. **key 行为必须可审计。** 业务事实须保留发起用户与 API key 身份，不能在排队、续跑或下属运行中丢失归因。上传也落一行，属主与 key 记在行上；签名者与 key 另随对象元数据存在桶里。
5. **凭证不进代码与 YAML。** 服务凭证只从环境变量读取；地址与非敏感配置的来源遵循 [配置模型](../server/src/iclip/config/models.py)，模型 `base_url` 可由 YAML 声明。必需变量缺失须在启动边界报告变量名，空串与空白视为未设置。
6. **运行生命周期由数据库持有。** 运行事实先落库，排队、恢复与续跑以数据库为准；客户端断开只结束订阅，不取消运行。
7. **运行目标只有一个声明事实源。** 配置声明 → 装配期冻结；路由、白名单、能力挂载都从它派生，不得各自重建平行映射。
8. **客户端铸的 id 只是幂等键，归属与权限永不由它决定。** 消息 id（`prompt_id`）、需求单 id 与对话 id 都可由客户端铸并按它幂等；重发同一个 id 不产生第二条记录。撞上别人的记录一律不交出去（按可见性返回 `404`），运行 id 仍由服务端发放。
9. **行级归属与操作权限分别判断。** 不可见资源不泄露存在性，可见但禁止的操作明确拒绝；治理者的读取范围不自动变成写入权限。跨端错误语义见 [错误处理约定](../contract/conventions.md#4-错误处理与响应信封)。
10. **付费外部调用不得因失败自动重投或替调用方换参数。** 提交是否受理不明时必须显式失败，不能靠重试猜测；模型与渠道由调用方指定，错误必须足以判断提交结果。持久化生成时刻使用数据库时钟。
11. **媒体引用保留原始身份，工具产物必须可追溯。** 模型媒体输入须在同一位置带媒体 tag，保留原始 URL 与种类；工具产出的地址须通过返回值或工作区文件交给模型，并按对话素材规则登记。tag 文法见 [harness/media.py](../server/src/iclip/harness/media.py)。
12. **压缩只改变模型窗口，不删除对话历史。** 摘要边界与完整消息共同持久化，Transcript 的轮次与终态仍从运行事实推导。

## 禁止逻辑

被刻意设计掉的推理模式，不得以「临时方案」名义重新引入：

- **信任客户端身份。** 任何来自 body / query / header（除凭证本身）的 userId、tenantId、role 都不得进入可信路径；run 按服务端事实定位，不按客户端提交的 id。唯一的口子是持 `users:act_as` 的 key 给的 `user_name`，它由入口一次换成主体，权限不随之改变，下游各处不得自己再解释这个字段。
- **把 key 当角色用。** 不得给 key 授予「随属主角色自动膨胀」的权限；扩权只能重新显式授予。
- **伪造终态。** 运行事实不完整时只允许显式可重试错误，或以已落库事实收尾；不为没有终态记录的 run 合成成功终态。轮的终态同理：只认官方记下的那条 run 结束事件，没有记录就是没跑完，不按消息形状猜一个出来。
- **无声接不上。** 客户端带水位续读而那些批次已出补批窗口时，服务端发一帧 `transcript.reset` 让它整页重拉；不跳到当前位置接着发。
- **静默兜底。** 必需配置缺失、持久化状态形状非法、协议边界损坏，都在最早的边界报错，不降级运行。
- **让模型自己认领素材。** 不能通过正文、工具参数、摘要或读文件补登素材，也不能用 URL 子串匹配代替台账精确查询。校验失败的报错不回显被拒地址。
