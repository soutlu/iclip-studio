# iClip-Agent 领域概念与核心规则

本文定义 iClip-Agent 的核心业务概念、系统不变量与禁止的设计模式，前后端共同遵守。
- 日常开发命令见 [../AGENTS.md](../AGENTS.md)
- 系统架构与模块分工见 [architecture.md](architecture.md)
- 接口与跨端协议见 [../contract/conventions.md](../contract/conventions.md)
- 历史架构决策见 [adr/](adr/)

## 上下文

- **产品定位**：iClip-Agent 是一款 AI 视频创作工具。用户通过与 AI Agent 对话推进视频制作：从拆解参考视频、编写分镜脚本或导演工程文件，到生成分镜图片、视频片段，最终在 `final-cut` 中剪辑配音并导出完整成片。
- **系统组成**：
  - `web/`：前端网页应用。
  - `server/`：视频业务后端（浏览器唯一访问的入口）。
  - `runtime/`：独立的 Agent 运行时服务，在私有项目 Cue 里开发，本仓库按 `runtime.ref` 钉住的版本检出到这里（不进本仓库）；`plugins/video/` 是安装在运行时里的视频工具插件包。
  - `render/`：独立的成片渲染服务。
  - **存储与外部依赖**：业务数据与运行状态存储在 PostgreSQL，图片与音视频文件存储在对象存储（OSS）。企业登录与组织架构接入 SSO / PMS，商品款式目录读取外部只读 PDM 库，平台爆款视频数据由部署方导入，大模型与音视频生成调用外部 AI 服务。
- **前后端边界**：后端负责定义接口与权限规则（以 [../contract/openapi.json](../contract/openapi.json) 为准），前端根据生成的接口类型实现交互（详见 [../web/AGENTS.md](../web/AGENTS.md)）。

## 术语

术语分为两部分：
- **运行时概念**：Agent 运行时服务通用的一套概念（底层细则见运行时项目的 `docs/CONTEXT.md`）。运行时本身只管跑 Agent，不管理具体的业务用户和权限；文中提到的管理权限（如 `agent:manage`）由视频后端在转发请求时检查。
- **视频业务概念**：本产品特有的业务模型。其中对话、测试预览和运行上下文在底层对应运行时的会话数据。

---

### 一、 运行时概念

#### 应用（App）
接入 Agent 运行时服务的业务后端（本产品的视频后端在运行时里登记为应用 `video`）。运行时信任接入的应用：当前操作的用户是谁、是否有权访问某段对话，均由业务后端判断；运行时只校验应用密钥，并原样记录后端传入的用户 ID。新系统接入指南见运行时项目的 `docs/apps.md`。

#### 会话（Session）
运行时用来承载一段对话的容器。消息记录、Agent 运行历史、聊天记录（Transcript）以及工作区文件都挂在会话下。会话归创建它的应用所有，不同应用之间完全隔离；在本产品中，会话 ID 直接使用业务侧的对话 ID。

#### 运行目标（Run Target）
一段对话绑定的顶层 Agent 及其固定版本。客户端只能选择用哪个 Agent，不能由前端直接指定底层模型或提示词：
- **创建时锁定版本**：用户新建对话时，只能选择首页公开、启用且已发布的 Agent。对话一旦创建，即锁定该 Agent 当时的最新版本；后续管理员发布新版本、回滚旧版本或归档该 Agent，都不会影响已有对话。
- **分叉时的版本**：从旧对话分叉出新对话时，默认沿用源对话锁定的版本；若分叉时切换了其他 Agent，则锁定新 Agent 当时的最新版本。
- **按次动态装配**：用户每发一条消息，系统按对话锁定的 Agent 版本加载模型、提示词和插件，并读取所绑定技能的最新发布版、子 Agent 的当前发布版。若该版本引用的模型已被停用、插件已移除或所属配置组缺少对应密钥，仅该对话提示无法发送消息，不影响其他对话。

#### 工具与工具集（Tool & Toolset）
- **工具**：大模型在运行过程中可调用的函数，包含名称、功能说明和参数定义。
- **工具集**：同一来源的一组工具。

#### 插件（Plugin）
写在代码里的内置工具集，目前共有 6 个：
- `workspace`（读写工作区文件，内置在运行时中）。
- `video`（理解视频内容）、`video_breakdown`（拆解参考视频）、`video_shots`（生成分镜表）、`shot_video`（视频抽帧与生成分镜图）、`iclip_studio`（校验导演工程文件）——这 5 个位于视频插件包中。
- 插件之间可声明依赖关系（如启用 A 必须同时启用 B），缺少依赖时无法发布或运行。
- `video` 插件调用的视觉理解模型固定在代码中，不随 Agent 配置改变；若后台未配置并启用对应的火山方舟模型，工具直接报错并让 AI 提示用户联系管理员开启。

#### MCP 服务（MCP Server）
管理员（需 `agent:manage` 权限）在后台接入的外部远程工具服务，通过标准 MCP 协议（支持 Streamable HTTP 或 SSE）提供工具：
- **基本配置与安全存储**：包含创建后不可改的唯一标识、服务名称、服务地址、超时时间和自定义请求头（名称与地址全局唯一）。服务地址和请求头的值均加密落库；管理接口返回完整地址，但请求头的值一律只返回脱敏打码值（如 `••••abcd`），编辑时未传项保留原值。
- **共享连接与使用自有账户**：默认共用后台配置连接；开启「使用自有账户」后，每位用户需在浏览器经标准 OAuth 登录授权一次以建立个人连接（登录链接 5 分钟内有效且仅限发起人单次完成；不支持动态客户端注册的服务需管理员预填客户端 ID 与可选密钥）。用户可主动断开连接，服务拒绝续期时状态变为「连接已失效」需重新连接。运行时按消息发送者本人的有效连接调用服务（后台请求头与传输配置照常生效，测试连接使用当前管理员自己的连接）；若用户尚未连接或连接已失效，当次运行跳过该服务的工具，不阻断对话。
- **配置变更影响确认**：修改服务地址或关闭「使用自有账户」会清空所有人的连接；缩小权限范围或更换客户端 ID 会使受影响的已有连接失效。涉及已连接用户时，保存前需管理员确认并展示受影响人数。
- **测试连接、工具挂载与审批**：支持保存前或保存后测试连接，成功后拉取并缓存工具列表（暴露给模型时自动加 `mcp_<服务标识>_` 前缀）。Agent 挂载服务时，每个工具可设为**允许**、**要求审批**（顶层运行调用前暂停等待用户同意或拒绝；子 Agent 不支持暂停，自动排除此类工具）或**关闭**（新挂载默认全关，全关时服务仍算已挂载但运行时不建连；历史 `tools: null` 代表包含服务后续新增工具在内的全部工具）。运行时连接服务失败会使当次对话运行报错。
- **引用保护**：凡被任一 Agent 草稿或当前版本挂载的服务禁止停用或删除；删除服务时同步清理其下全部用户连接。

#### 技能库（Skill Library）
供 Agent 按需加载的专业知识与操作指南库（仅 `agent:manage` 可见可管理）。每个技能由主文档 `SKILL.md`（头部 YAML 声明 `name` 和 `description`）以及 `references/` 目录下的参考文本文件组成：
- **标识与名称**：技能标识 `name` 全库唯一。标识和显示名称属于技能自身属性，修改后立即生效，不随版本回滚改变；运行时加载或导出 zip 包时，自动把 `SKILL.md` 里的 `name` 替换为当前标识。
- **草稿编辑**：所有修改先在草稿上进行（支持增删改文件、重命名、zip 导入覆盖草稿、将历史版本恢复到草稿）。主文件 `SKILL.md` 禁止删除或改名；修改单文件需携带读取时的内容哈希（`baseHash`）防止并发覆盖。
- **发布版本**：校验无误后发布为不可变的新版本（版本号从 1 递增，支持导出 zip）；草稿与最新发布版完全一致时拒绝重复发版。
- **运行期加载**：模型按需加载技能后，通过 `read_skill_file` 按相对技能目录的路径读取 `references/` 下的参考文件。

#### 模型声明（Provider Declaration）
随代码发布的模型供应商接入规范（每家供应商一份 YAML，启动时校验），规定支持的接口协议（`responses`、`chat` 或 `gemini`）、密钥必填字段以及各接口协议允许配置的原生工具，不包含模型清单：
- 模型按 `(模型名, 类型)` 唯一区分，类型分为对话模型 `llm`、向量模型 `embedding` 和重排模型 `rerank`。
- `llm` 模型必须指定接口协议，并可配置上下文窗口大小、可选思考档位（未配置则不支持调节思考深度）和原生工具（由模型厂商在其服务端执行的工具，如联网搜索；可用名录与各接口允许范围由运行时维护，应用按接口动态读取，详见运行时项目的 `docs/CONTEXT.md`）。
- 目前内置阿里云百炼、Google Gemini、OpenRouter、火山方舟与 OpenAI 兼容 5 份声明。

#### 供应商（Model Provider）
管理员（需 `model:manage` 权限，默认仅 root 拥有）根据「模型声明」在后台实际接入的模型服务商：
- **模型管理**：新接入的供应商默认不含模型，由管理员自行添加（添加后即启用）；所有模型均支持修改属性、启停与删除。
- **权限隔离**：持 `agent:manage` 的配置人员只能看到已启用的供应商、已启用的对话模型和脱敏后的密钥名称，看不到明文密钥。
- **固定模型**：系统中有四处功能不走 Agent 配置，直接在代码中指定了固定的火山方舟模型——**视频理解、参考视频拆解、资料库自动打标、final-cut 文字翻译**。每次调用时，系统自动寻找已启用、开启了该模型且配有对应密钥（未分组用默认密钥，归属配置组则用该组密钥）的火山方舟供应商；找不到可用配置时返回「模型未启用」错误。所有密钥均保存在运行时服务内，业务后端通过运行时代理调用。

#### 密钥（Provider Credential）
模型供应商的接入凭证（如 API Key 和接口地址），同一供应商下可配置多把密钥：
- **默认密钥**：添加的第一把密钥自动设为默认密钥；删除默认密钥前必须先将默认切换到其他密钥。
- **加密与脱敏**：敏感字段加密存储，接口一律只返回打码值（`••••` 加末 4 位）。保存密钥只校验必填项，不强制联网测试。
- **连通性测试**：支持保存前用表单内容测试连接（向该供应商首个已启用的 `llm` 模型发最小请求），也支持用已保存密钥单独测试指定模型。

#### 默认模型（Default Model）
每种模型类型（如 `llm`）可指定一个全局默认模型。`llm` 默认模型用于为新对话自动生成标题（未设置则不自动生成）；被设为默认的模型禁止停用或删除。

#### Agent 标识、草稿与版本（Agent Config）
- **Agent 标识（Agent ID）**：每个 Agent 的唯一英文代号（小写字母开头，仅含小写字母、数字和连字符，最长 40 字符，创建后不可修改）。Agent 还包含名称、功能描述（作为子 Agent 被调用时展示给主 Agent，修改立即生效）、首页上架开关、排序位置及归档状态。
- **草稿（Draft）**：正在编辑的 Agent 配置（系统提示词、所选模型及其思考档位与原生工具、插件、MCP 工具、子 Agent 及有序技能列表）。保存草稿使用 `lockVersion` 乐观锁防覆盖，允许暂不完整（如尚未选模型）。
- **版本与发布（Version & Publish）**：发布时全面编译检查草稿引用的模型、密钥、插件依赖、MCP 服务、技能和子 Agent 是否全部可用，不通过时一次性返回全部错误字段路径；通过后生成不可变新版本（从 1 递增）并设为**当前版本**。
- **引用保护**：只要某个技能、模型、密钥、供应商、MCP 服务或子 Agent 正被任一 Agent 的**草稿或当前版本**使用，系统即拦截对其的归档、停用或删除，并指明引用方（仅被历史旧版本引用不拦截）。

#### 子 Agent（Sub-agent）
主 Agent 可将任务委派给其他已发布的 Agent 执行（可配置单次超时、最大调用次数和失败提示语）。**子 Agent 最多只允许一层嵌套**：作为子 Agent 的不能再挂载下一级子 Agent，已挂载子 Agent 的也不能被选作子 Agent。

#### 导出包（Agent Package）
将某个主 Agent 及其所有子 Agent 的当前版本配置打包导出的 YAML 文件（自动剔除环境专属的密钥 ID）。导入支持先预检（`dryRun`）再正式写入：同 ID 已存在则仅覆盖其草稿，不存在则新建草稿，导入后均不自动发布。

#### Agent 运行与聊天记录（Agent Run & Transcript）
- **Agent 运行**：大模型一次执行的底层持久化记录。用户发一条消息（一轮 Turn）若中途触发人工审批并恢复执行，底层会产生多次运行（Run）。
- **模型上下文（Model Context）**：单次发给大模型的消息窗口。触发「上下文压缩」时，系统在历史中插入摘要分界线，后续仅将「前文摘要 + 分界线后的新消息」发给模型；原始消息完整保留，前端展示的历史记录不受影响。
- **Transcript**：将底层运行记录投影为前端直接渲染的树状结构：`轮（Turn）→ 步（Step）→ 块（Block：正文、思考、工具卡片等）`，协议见 [../contract/conventions.md#5-agent-对话-transcript](../contract/conventions.md#5-agent-对话-transcript)。
- **对话用量（Conversation Usage）**：按对话和模型累计调用次数与 4 类 Token 消耗（普通输入、缓存命中、缓存写入、输出），含子 Agent 消耗；自动起标题、上下文压缩摘要和视频理解工具的消耗不计入。

### 二、 视频业务概念

#### 1. 身份、角色与运行上下文

##### 主体与双主体（Principal）
代表当前请求发起者的可信身份，包含所属用户、API Key 信息（如有）、最终生效的权限集合及用户名。系统所有功能同时向「浏览器登录用户」和「携带 API Key 的机器调用方」开放，后端统一解析为同一种 `Principal` 结构（见 [../contract/conventions.md#2-双主体认证-dual-principals](../contract/conventions.md#2-双主体认证-dual-principals)）。

##### API Key 与代指定用户操作（`users:act_as`）
- **API Key**：挂在用户账号下的长期访问令牌（需 `api_keys:issue` 权限签发）。权限在签发时显式勾选，不得超过签发人当时的权限，也不会随所属用户后续扩权而自动膨胀。
- **代指定用户操作**：持有 `users:act_as` 权限的 API Key 在调用指定的 13 个写接口（建对话、建需求单、发消息、对话运行控制（停止、撤消息、插话、审批、重新生成）、改对话工作区文件、提交生成、参考视频试生成、添加参考音频、确认上传）时传入目标用户名，以该用户的身份操作：新产生的数据直接归属到该用户名下（若该用户尚未登录过系统，自动创建同名占位账号，待本人日后通过 SSO 登录时自动认领），操作已有对话须填对话属主。操作权限仍按该 API Key 自身权限校验，审计记录标记为 `目标用户名#Key名称`。无 `users:act_as` 权限的 Key 传 `user_name` 仅作上游对账标签，不切换数据归属。

##### 角色（Role）
一组权限的打包名称，用户最终权限 = `角色权限并集 ∪ 直接权限`（见 [rbac.py](../server/src/iclip/domains/identity/rbac.py)）。**SSO 新账号默认只读**：首次通过企业 SSO 登录创建的新账号默认赋予只读角色 `viewer`（匹配配置 `sso.root_email` 的邮箱首次登录自动授予 `root`），须由管理员在「设置 → 用户」中分配写权限角色（如 `editor`）后方可执行对话创作与媒体生成。**防越权原则**：管理员修改他人账号时，不能管理权限超出自己范围的用户，也不能授予自己不具备的权限。

##### 运行依赖（Run Deps）
Agent 运行期间携带的上下文（对话所属用户 ID、对话 ID、所属配置组、是否为测试预览及上游对账 `user_name`）。Agent 工具执行受控操作时，始终按所属用户 ID 实时查询该用户当前的最新角色权限，不使用发消息时那把 API Key 的权限。

#### 2. 对话、测试预览与制作流程

##### 对话（Conversation）
用户进行视频创作的聊天窗口，工作区文件按对话严格隔离：
- **可见性与软删除**：普通用户只能看到自己未删除的对话；删除仅做软删除标记（「墓碑」），底层运行记录、工作区文件和生成视频均保留，已删除对话禁止任何修改。持有 `users:manage` 的治理者可只读查看和复盘全站所有对话（含已删除对话），不可修改他人对话。
- **关联需求单与合集**：每段对话最多关联 1 张创作需求单和 1 个对话合集，支持随时绑定或解绑。
- **分叉（Fork）**：任何有权查看该对话的用户（含治理者查看已删除对话），均可从任意一轮分叉出归属自己的新对话。新对话复制截至该轮的聊天历史与工作区文件；源对话此前已生成的视频与已挂载的上传不复制物理数据，通过**继承关系**在新对话中只读可见（分叉副本不计入审计报表）。
- **做同款**：在资料库浏览带有工程文件（`film.icml`）或分镜文件（`video_shot.json`）的素材卡时，即使无权访问源对话，也可一键将源对话的制作文件复制到一段全新空白对话中改写新片（不复制聊天历史，也不继承原视频）。
- **四个独立状态维度**：
  1. **运行忙闲（`busy`）**：当前是否有对话轮次正在执行（等待人工审批或提问回复时也算 `busy`）。
  2. **人工交互（`pendingInteraction`）**：是否暂停在审批（`approval`）或提问（`question`）。
  3. **上轮结局（`lastTurnReason`）**：最近一轮是正常完成（`completed`）、失败（`failed`）还是被中止（`aborted`）。
  4. **视频生成进度**：该对话下是否有视频（出片、编辑段、衔接段、合成）正在排队或生成中（`none / queued / running`）；后台生成视频不占用对话轮次，不算 `busy`。
- **已收尾标记**：由对话创建者手动标记「已收尾」；创建者继续发消息或提交新的视频生成（出片、编辑段、衔接段、合成）时自动取消收尾标记（字幕识别、配音/合成语音、生成背景音乐、导出成片不取消该标记）。

##### 测试预览（Agent Preview）
供管理员（持 `agent:manage`）在后台试聊草稿或指定历史版本的专用通道：
- **与正式对话完全隔离**：不进入对话列表、侧边栏、统计与审计报表，不支持分叉或做同款，预览中生成的图片不关联业务对话 ID。
- **实时加载草稿**：预览草稿时，每条消息实时读取最新保存的草稿配置（技能取最新发布版、子 Agent 取当前版本）。配置页存在未保存的修改时，发测试消息或重新生成前先自动保存草稿，保存失败则取消发送；一条消息开始运行后再保存的修改，从下一条消息起生效。
- **严格私有**：仅发起人本人（且仍持有 `agent:manage`）可见可用，**全站治理者也不可查看他人的测试预览**。每人在每个 Agent 下只保留一段有效预览，开启新预览自动中断并替换旧预览。

##### 合集（Collection）
用户整理自有对话的文件夹。普通用户仅管理本人合集；治理者可查看、重命名或删除全站合集。

##### 媒体地址（Media Address）
工具与制作页统一接收完整 HTTP(S) 媒体 URL，不限制地址来源（不要求曾在对话中出现），遵循**「提交时校验，读取时直取」**原则：
- **提交时校验**：交付分镜表、校验工程文件、按节点生图、出镜头帧、拆解视频，以及在制作页插入/选用图片或发起生图/出片时，逐一检查链接可达且媒体类型匹配；首次网络失败自动重试一次，仍不通过则按位置报错（「打不开」或「不是图片 / 视频」）。
- **读取时直取**：读图、打开制作页、视频理解及抽帧下载阶段不预检地址，无法拉取时由实际读取步骤如实报错。
- **出网安全**：由实际发起网络请求的服务端组件负责公网地址校验与内网隔离（见 [architecture.md](architecture.md#身份与模块协作)）。

##### 镜头组（Shot Group）
分镜脚本（`video_shot.json`）的基本单元，用从 1 开始的**镜号**（`shots[].index`）标识：
- **镜头帧**：镜头组引用的第 N 张参考图，在提示词正文中用 `@ImageN` 引用。
- **版本组**：对话下所有可用视频（含分叉继承）按镜号分组，组内按完成时间自动编号为 `V1, V2...`，便于在多版生成与合成结果间对比切换。

##### 导演工程文件与制作页（Film Project & Film Page）
AI 导演制作短片时维护的一对工作区文件及前端可视化编辑页（接口见 [../contract/conventions.md#6-对话-conversations](../contract/conventions.md#6-对话-conversations)）：
- **内容文件 `film.icml`**：定义人物/场景/道具设定、配音音色、拍摄手法、剧本台词（`<script>`），以及各生图节点和视频分段请求的参数与参考图列表（正文通过 `@Image1..N` 引用列表图片；存在未选图的槽位时禁止发起对应生图或出片）。
- **运行文件 `film.icrun`**：记录所有候选图片 URL，并通过 `use` 语句指定每个生图节点当前生效的选用图片（新生成的图片仅作为候选，须写入 `film.icrun` 选用后才生效）。
- **制作页交互**：将两个文件渲染为可视化分镜卡片，支持直接修改文案与台词、增删单组参考图、选用或更换图片、一键切换全片画幅，以及直接点击发起节点生图或分段出片；打开页面仅校验文件语法，插入/选用图片与提交生成前才校验图片地址。

##### final-cut、成片与成片导出
- **final-cut（剪辑工程）**：对话工作区 `final-cut/` 目录下的多轨合成工程（无时长上限；界面固定写作小写带连字符的 `final-cut`，与中文相邻两侧留空格），仅在工作区存在主文件 `final-cut/index.html` 时显示工作台「final-cut」页签（未创建时可通过工作台「+」按默认 `9:16` 模板显式新建，或由 Agent 创建；向尚无视频片段的轨道首次加入视频时，画布自动适配该视频比例）。主文件 `final-cut/index.html` 是唯一主时间线，浏览器预览（运行于独立预览域名沙箱）与服务端渲染直接共用同一份 HTML 工程，支持编辑器可视化操作（含舞台右上角「画面设置」浮层，用于调整画幅比例、偶数像素尺寸、画布底色及仅编辑器可见的构图网格与安全区参考线；修改画布尺寸或底色不换算已有片段位置与单句自定义字号）与 Agent/手写修改（工程文件格式见 [../contract/conventions.md#final-cut-工程格式](../contract/conventions.md#final-cut-工程格式)）。
- **轨道分区与四类片段**：时间线分为上方的**画面区**（首行主轨承接默认追加与波纹补位，跨行重叠按叠放顺序 `z-index` 遮挡）、下方的**声音区**（按音频来源分为「配音」「原声」「配乐」三类专属轨道，互不混放）以及两区之间独立的**字幕轨**；同行片段禁止时间重叠，支持片段切分、隐藏/静音、配乐节拍分析与吸附（缓存于 `final-cut/beats/`），以及画布上直接拖拽（含画布与图层对齐吸附）、缩放、旋转与原地改字（视频片段与单句字幕各自独立编辑；元素与模板作为整体图层编辑，变换写入主文件宿主，不改动组件文件，多个片段共用同一组件互不影响）：
  - **视频片段**：引用本对话（含分叉继承）的素材片；仅在探出音轨时默认开声（无音轨强制静音且不可取消），支持将原声分离为独立原声片段并与画面联动或口型对齐。编辑器「镜头」页签按镜头组列出各条出片（原片及其合成版本），每条出片的版本各自从 `V1` 编号（`V1` 为原片，合成版本按完成时间依次为 `V2, V3...`），与「版本组」按整个镜头组编号是两套编号。
  - **元素与模板**：引用公共组件库的组件（界面称「元素」）或块（界面称「模板」）。选用时将条目专有文本文件按原路径拷入 `final-cut/` 归当前工程独立持有，`vendor/` 公共依赖仍读取共享目录。
  - **音频片段**：引用本对话（含继承）生成的背景音乐、对话上传音频、参考音频库的配乐/音效，或配音与旁白片段。所有有声片段（含开声视频片段）共享一套跨语言的智能调音效果链（声音角色分组、遇人声自动压低、自动平稳音量、音色风格预设、均衡/升降调/效果器及波形音量关键帧）。
  - **其他片段**：手写或组件库目录外的时间线元素，仅支持基础起止、换行与显隐调整。
- **字幕、多语言与按语言配音**：
  - **字幕与旁白**：原片自带语言统称「原文」（无需声明语种）。可按视频片段识别口播字幕（归属并跟随该视频片段移动、删除与切分；一句话跨过相邻镜头时仅归属播出其开头的有声片段并保留整句起止时间，对应配音长度上限同步放宽至字幕结尾），也可手动增改字幕，或输入文案调用语音合成在时间线插入对齐的「旁白片段 + 字幕」。在「字幕」页签原文视图下，若镜头组素材片（非编辑/合成片）已有识别记录且识别字幕与原始台词存在差异，该句下方展示台词差异对照并支持一键「采用」（仅读取已有识别记录，不主动发起识别）。字体（限组件库已声明字体）、字号与字色按「字幕样式」整轨设置，未开启「单独设置」的句子统一跟随；单句开启「单独设置」后改为使用自身的值（开启时沿用当时的显示效果），不再随字幕样式变化，关闭后重新跟随。两者均全语言共用，字幕仅支持整轨隐藏。
  - **多语言值表**：工程可添加 `zh / en / de / es / fr` 语言值表（`final-cut/locales/<locale>.json`）。字幕与设为「随语言」的元素/模板文字字段按当前所选语言预览和导出（首次添加外语时文字字段默认转为随语言，用户可切为固定；未翻译项回退原文）。
  - **按语言人声模式**：每种附加语言独立设置「保留原声」或「AI 配音」（指定整体音色——原声克隆或参考音频库音色，并支持单句单独指定音色或设为不配音；配音片段与所属字幕双向跟随移动）。预览与导出时，AI 配音模式仅播放当前语言配音并自动静音原片人声与原文旁白；原文及保留原声模式播放原片人声与原文旁白、屏蔽外语配音。
- **成片与成片导出**：正在编辑的工程称 `final-cut`，提交独立渲染服务（`render/`，单任务先进先出排队，超时 6 小时）按指定语言和导出分辨率档位渲染产出的 MP4 视频才称**成片**（资料库「成片」页签与下载成片均指该产物）。导出分辨率（480P / 720P / 1080P）为单次导出请求参数，不写入工程文件且不改动画布尺寸；仅 16:9、9:16、1:1 画幅支持切换至其他预设档位（支持缩小，放大仅允许整数倍），具体兼容性由渲染服务依据导出库预设规则判定。导出读取渲染启动时刻工作区内的实时工程文件，不保存工程历史快照；导出记录保存目标语言、分辨率档位及匹配到的素材血缘（视频匹配生成记录；音频依次匹配本对话含继承的生成记录、对话上传、参考音频库，未匹配不阻断导出）。详见 [../contract/conventions.md#成片导出](../contract/conventions.md#成片导出)。

#### 3. 媒体生成任务、资料库与标签

##### 生成任务（Generation Job）
调用生成模型或由系统加工产出受管媒体文件（剪辑合成、宫格切图、成片导出等）时，均在数据库中记录一条生成任务；用户上传文件独立记入上传台账，不进生成任务。
- **素材片**：指已生成完成、可完整播放的**出片（原始生成视频）**或**合成视频（剪辑拼接视频）**。局部替换用的「编辑段」、接两条素材片用的「衔接段」、参考视频「试生成」、「导出的成片」和「超分高清版」均不属于素材片。
- **13 种生成记录类型对比**：

| 记录类型 | `kind` | `operation` | 来源 `source_job_id` | 原作 `root_job_id` | 关联对话 | 取消对话已收尾状态 | 计入对话视频生成进度 | 进入全站资料库 | 计入审计报表 |
|---|---|---|---|---|---|---|---|---|---|
| **出片**（素材片，含样片与转出的 1080p） | `video` | `generate` | 无 | 无 | 可选 | 是 | 是 | 成片素材 | 是（有镜号且关联对话） |
| **试生成**（验证参考视频拆解） | `video` | `trial` | 无 | 无 | 无 | 否 | 否 | 否 | 否（视频生成报表里单列） |
| **编辑段**（局部重绘） | `video` | `generate` | 基底素材片 | 最初出片 | 可选 | 是 | 是 | 否 | 否 |
| **衔接段**（接两条素材片的过渡） | `video` | `generate` | 左边那条素材片 | 随左边那条 | 可选 | 是 | 是 | 否 | 否 |
| **合成**（素材片） | `video` | `compose` | 基底素材片 | 最初出片 | 可选 | 是 | 是 | 成片素材 | 否 |
| **文生图 / 帧图编辑** | `image` | `generate` | 无 / 底图记录 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **宫格切图** | `image` | `cut` | 宫格原图记录 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **字幕识别记录** | `subtitle` | `generate` | 被识别的素材片 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **配音记录** | `dubbing` | `generate` | 被配音的素材片 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **合成语音**（旁白配音） | `speech` | `generate` | 无 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **生成背景音乐** | `audio` | `generate` | 无 | 无 | 必填 | 否 | 否 | 否 | 否 |
| **成片导出记录** | `whole_film` | `render` | 无 | 无 | 必填 | 否 | 否 | 成片 | 否 |
| **高清版（超分）** | `video` | `enhance` | 素材片或成片 | 无 | 否 | 否 | 否 | 否 | 否 |

- **核心规则**：
  - **不自动重试**：所有付费生成任务一旦失败即为终态，后台绝不自动重新提交（见不变量 10）。
  - **两层血缘（来源与原作）**：对视频做局部重绘（编辑段）或剪辑拼接（合成）时，`source_job_id` 指向直接基于的那一版素材片，`root_job_id` 始终指向最源头的原始出片，便于一键拉出整条修改链。
  - **样片与转 1080p**：样片属于出片的一种——先生成 480p 样片，完成后可转为 1080p（仅当部署开通样片功能时可用，开通后视频模型清单方列出支持样片的模型）。转出的 1080p 为同一镜头组下的新出片（素材片），不记录来源与原作，请求快照保存对应样片 ID；同一条样片在同一对话下仅保留一条未失败的转出记录。
  - **字幕按需识别**：素材片完成后不自动识别字幕，仅在显式调用识别接口时创建任务（无音轨或无人说话同样正常完成，结果为空列表）。
  - **配音与合成语音**：配音（`dubbing`）按参考音频（素材片原声、参考音频库音色或本人音频上传）逐句合成译文并拼成与素材片等长的 m4a 音轨；合成语音（`speech`）用参考音频库音色合成单句旁白音频（不绑定素材片、不补静音）。两者共用同一语音合成通道，均不归入 `kind=audio` 背景音乐列表。
  - **试生成隔离**：试生成与出片走同一视频网关与配置组，记为 `operation=trial`；不可用于识别字幕、配音或超分，不进入资料库，仅支持下载与还原度对照。
  - **超分高清版全站共享**：任何人均可对素材片或成片发起更高分辨率超分；同一源视频的同一清晰度档位全站只保留一条未失败记录供所有人共用。

##### 配置组（Model Group）
按用户隔离媒体生成与大模型调用凭证的配置单元，包含组名、各媒体服务（视频、字幕识别、背景音乐、配音）专属 API Key、「产品模型名 → 网关 `model_id`」映射表，以及在管理后台绑定到该组的大模型密钥（运维配置见 [deploy.md#配置组](deploy.md#配置组)）：
- **用户归组**：配置组在部署配置中定义，由 `root` 在网页「设置 → 用户」中为各成员分配并持久化至数据库用户记录，即时生效、无需重启。未分配配置组的用户归属**默认组**：媒体生成使用部署配置中保留组名 `default` 对应的密钥与 `model_id`（`default` 不可分配给用户），大模型调用使用未绑定配置组的密钥。SSO 登录同步不覆盖用户的配置组。
- **组失效不回退**：用户绑定的配置组已不在部署配置中（含部署配置不再声明任何可选配置组）时，按该用户定组的入口（发消息、媒体任务受理、`final-cut` 翻译）直接报错并提示联系管理员重新分配，绝不回退默认组或默认密钥。
- **媒体任务受理时定组**：出片、试生成、编辑段、衔接段、高清版、字幕识别、背景音乐、配音与合成语音在受理时按记录属主（代操作时为目标用户；共享高清版按首次发起人；样片转出的 1080p 沿用样片记录的组名与 `model_id`）锁定组名与上游 `model_id` 写入任务记录，后续提交与轮询不再按人重查（默认组的组名一列为空，其余记录类型不分组；`video_generation_report` 视图末尾输出 `model_group` 与 `upstream_model`）。
- **大模型密钥归组与调用归属**：后台同一供应商下每个配置组最多绑定一把密钥，有组用户调用大模型时严格使用该组密钥，绝不回退默认密钥。发消息（含测试预览）、自动起标题与 `final-cut` 翻译按对话属主定组（重新生成沿用原消息组）；参考视频拆解按触发人定组；资料库打标按条目创建人定组（无记录人时走默认组）。
- **组缺密钥处理**：发消息所需供应商（含子 Agent）缺少该组密钥时直接以 `409 agent_unavailable` 拦截；自动起标题静默跳过；拆解、打标与翻译按「模型未启用」处理。

##### 继承（Inherited Records）
对话分叉后，新对话对源对话（及更早祖先对话）在分叉时刻前已有出片记录与挂载上传的**只读引用关系**：新对话可直接查看、下载这些视频或将其作为剪辑/修图基底，但不能对继承来的旧轮次点「重新生成」，原始归属人与所属对话保持不变。

##### 生成结果（Generation Output）
- **图片与背景音乐**：上游返回的临时链接必须由服务端下载处理（音乐切除首尾静音并统一响度）后转存为本系统 OSS 永久公开链接才算成功，转存失败则任务记为失败。
- **视频**：上游生成视频必须同时具备「无水印原片」与「带水印预览片」两个稳定地址才算成功；本地合成视频与导出成片直接存入 OSS，仅无水印版。

##### 上传与上传台账（Media Upload）
前端直传 OSS（先 `sign` 签名、再 `confirm` 确认）或发消息时服务端自动转存的外部图片，统一记入独立的**上传台账**（`iclip.media_uploads`），不写入生成任务，下载也不记埋点：
- **元数据记录**：确认时记录 OSS 返回的内容类型、字节大小与 MD5，图片额外记录签名时上报的宽高（服务端转存直接读图片头）；确认阶段不探测音视频时长，参考音频入库时才实测时长。
- **视频按 MD5 去重**：不同用户上传相同 MD5 的视频时，OSS 仅保留最早一份物理对象地址，但仍为每次上传各自建立台账记录；图片与音频不去重。
- **关联对话与使用边界**：任意类型上传确认时均可挂载到本人对话（分叉对话自动继承分叉前挂载的上传），挂载音频可直接供该对话 `final-cut` 选用。配音上传参考音频及参考资产入库均仅允许使用调用者本人的上传记录；以上传图片为底图修图时按外部底图地址记录。

##### 资料库（Library）
面向全站用户（持 `generation:read`）开放的创作成果与素材复用中心，包含 5 个板块：
1. **成片素材（素材卡）**：按对话聚合展示全站生成的素材片（按镜头组与版本排列，原对话软删除后照常展示）；工作区含工程文件或分镜文件时支持一键**「做同款」**。
2. **灵感库（参考视频，Reference Video）**：按视频 URL 唯一沉淀的参考视频、AI 拆解报告（Markdown）与分类标签（来源包括资料库手动入库的本人上传/可见素材片，以及 Agent 对话内拆解的外部链接）。仅首次创建者或治理者可修改报告、重拆、移除，或发起**试生成**（记录最新一次试生成任务）；移除后对话内按同地址拆解仍复用已有报告，但不会重新上架资料库。
3. **音频库（参考音频，Reference Audio）**：收录音色（`voice`，3～30 秒，可附语种与台词供配音克隆）、配乐（`bgm`）与音效（`sfx`）三类音频，来源为本人音频上传或可见的生成背景音乐（入库时解码一遍，实测时长并算出波形峰值；不去重）。三类各有自己的选填属性，不能跨类填写：音色有性别、年龄段与至多 2 个使用场景，配乐有情绪、曲风与 BPM，音效有类别。属主或治理者可编辑元数据与属性或移除；音色与配乐/音效分别在 `final-cut` 的配音与配乐面板中选用。
4. **爆款素材库（Hit Case）**：从「成片素材」中精选出的优秀单版视频（要求所属对话工作区含新片执行方案 `treatment.md`），入选后自动读取 `treatment.md` 触发 AI 打标。
5. **成片（成片卡）**：按对话聚合展示全站已导出的完整成片（含历史导出版本 `V1, V2...`），支持标题搜索与下载。

##### 参考资产（Reference）
参考视频与参考音频统称参考资产，共用一套 ID、属主、来源与软删除机制；提交视频出片时可传入本次引用的参考资产 ID 列表（`reference_ids`，须均在库且未移除）留存归因记录。

##### 标签（Library Tag）
灵感库与爆款素材库共用的分类标签树（顶层为「维度」，维度下最多 3 级标签值，由管理员动态配置）：
- **AI 自动打标 vs 人工打标**：维度可开启 `auto_fill: ai`。参考视频拆解完成或爆款素材入选时，后台调用大模型整组覆盖所有 AI 维度标签，人工维度保持不动；打标进行中禁止手动改标。
- **筛选逻辑**：同一维度内多选为「或（OR）」（勾选父标签自动包含全部子孙标签），不同维度之间为「且（AND）」。

#### 4. 创作需求单、外部商品库与审计统计

##### 创作需求单（Task）
派发视频创作任务的工单（含视频规格、1～20 款商品快照、分类参考素材和创作要求，持 `tasks:read` 全站可见）：
- **生命周期**：`草稿（draft）→ 已下发（published）→ 已认领（confirmed）→ 已撤回（withdrawn，终态）`。草稿仅创建者或治理者可改可删；下发后商品列表与核心视频规格冻结不可改。
- **多人认领与自动认领**：一张需求单支持多人认领；只要用户将自己的对话关联到已下发需求单，系统即自动将该用户记为认领人（详见 [../contract/conventions.md#8-创作需求单-tasks](../contract/conventions.md#8-创作需求单-tasks)）。

##### PDM 款目录与爆款视频（Inspiration Video）
- **PDM 款目录**：连接外部只读商品库，查询商品款号对应的「品牌」与「品类」编码。
- **爆款视频**：部署方导入的历史高表现带货视频库；按款号检索无果时，自动按「同款 → 同品牌同类目 → 同类目」三级回退寻找替身视频。

##### 埋点事件（Tracking Event）
前端上报的用户行为记录（目前仅 `video.downloaded`）。每次成功下载记一条事件，`jobId` 为实际下载文件对应的任务记录（素材片、编辑段、高清版或成片），下载失败不记；素材片归因在查询报表时按血缘实时汇总。

##### 审计口径（Audit Metrics）
治理者查看团队产能、一次通过率、耗时与 Token 消耗的统一统计标准（**分叉副本、局部编辑段、衔接段、合成视频、无镜号或未关联对话的视频均不计入产能**）：
- **出片件数（Deliveries）**：有成功出片的需求单算 1 件；未关联需求单但有成功出片的独立对话也算 1 件。
- **镜数与一次通过率**：同一对话下同一镜号成功生成至少 1 条视频算 1「镜」；该镜仅成功生成 1 次即定稿（中间失败不计，成功后重生成则不计）称为**一次通过**。样片转出的 1080p 照常计入出片数、片长与有效镜，但不计为该镜的新增出片尝试，不影响一次通过率判定。
- **有效镜与有效率**：某镜视频或其衍生出的编辑段、合成、成片、高清版被任意用户下载过至少 1 次即算**有效镜**，`有效率 = 有效镜数 ÷ 总镜数`。
- **视频生成报表**：只读视图 `iclip.video_generation_report`，每行对应一条成功或失败的出片或试生成（末尾 `trial` 列区分，编辑段不单列），下载归因口径与有效镜一致。
- **废片时长**：同一镜成功生成多条视频时，除最后完成的一条外，其余早期成功视频均计入**废片**总时长。
- **交付周期与单任务有效时长**：对话首次运行到末条视频完成的总跨度为「交付周期」；剔除超过 30 分钟闲置空档后的实际活跃累计时段为「单任务时长」。
- **四类任务执行异常**：`反复重试`（单镜成功生成 ≥ 3 次）、`视频悬挂`（提交上游超 1 小时未返回）、`消耗离群`（单对话 Token 超当期件均 3 倍）、`需求单卡住`（关联 ≥ 3 段对话尝试仍零出片）。

## 不变量

每一条代码路径都必须严格遵守以下 12 条底线规则：

1. **PostgreSQL 是唯一的持久化事实源。** 进程内存不能用来承担跨进程的业务正确性；前端的实时流投影和内存缓存都只是派生视图。
2. **可信身份只来自入口建立的 `Principal`。** 每个请求只在入口中间件解析一次登录态或 API Key；下游业务代码严禁自行解码凭证或轻信客户端传来的 `userId` / `role`。唯有持有 `users:act_as` 的 API Key 可以在指定的 13 个写接口入口按目标用户名切换一次归属用户。
3. **权限集合是唯一的授权依据。** 已过期、已吊销或所属账号已停用的 API Key 必须直接拒绝，绝不能回退使用所属用户的个人权限。
4. **API Key 的操作必须全程可审计。** 数据库记录与 OSS 对象元数据都必须同时保留「实际归属用户」与「调用方 API Key 身份」，在异步排队或子 Agent 运行中不得丢失。
5. **敏感凭证绝不进代码与配置文件。** 所有密码、Token 和密钥只从环境变量读取；必填环境变量缺失或为空白字符串时，服务必须在启动阶段直接报错退出并指明变量名。
6. **运行生命周期由数据库驱动。** 消息入队、运行状态流转、崩溃恢复与审批续跑一律以数据库记录为准；浏览器断开 WebSocket 只取消消息订阅，不会中止后台正在运行的任务。
7. **Agent 运行配置只有一个事实源。** 首页可选 Agent 列表、对话锁定的版本、挂载的插件/技能与模型配置全部从运行时数据库派生，不再读取本地静态 YAML 配置。
8. **客户端生成的 ID 仅作幂等键，绝不决定数据归属。** 消息 `prompt_id`、对话 `id` 与需求单 `id` 支持客户端生成以实现重试幂等；如果与系统中其他用户的记录 ID 撞车，一律按不可见返回 `404`。
9. **「看不看得见」与「能不能改」分开判断。** 无权查看的资源统一返回 `404`（不暴露该资源是否存在）；有权查看但无权修改的资源明确返回 `403`。治理者的全局查看权限绝不自动变成修改权限。详见 [../contract/conventions.md#4-错误处理与响应信封](../contract/conventions.md#4-错误处理与响应信封)。
10. **付费生成任务一旦提交，后台绝不自动重试或擅自篡改参数。** 如果请求发给上游后超时、不确定上游是否已受理计费，必须明确标记为失败，不能盲目重投。是否重新发起一次付费生成由调用方策略决定（例如分镜出图工具配置了「先试 dev 渠道、失败再起一个新任务试 pro 渠道」，属于显式新建任务）。
11. **发给模型的媒体必须保留原始标识，工具产出的媒体必须可追溯。** 传给大模型的图片/视频必须带有包含原始 URL 和类型的媒体标签（见运行时项目的 `src/agent_runtime/harness/media.py`）；工具产出的媒体地址必须通过返回值或工作区文件交给模型。
12. **上下文压缩只缩短发给模型的窗口，不删除历史记录。** 压缩摘要边界与原始消息共同保存在数据库中，界面展示的历史轮次不受压缩影响。

## 禁止逻辑

以下设计模式在系统中被明确禁止，不得以「临时方案」名义引入：

- **禁止信任客户端传来的身份字段**：除 `users:act_as` 专用入口外，严禁读取请求体、Query 或普通 Header 中的 `userId`、`tenantId`、`role` 作为鉴权依据。
- **禁止让 API Key 权限随用户角色自动膨胀**：API Key 只有创建时显式勾选的权限，需要新权限必须重新签发。
- **禁止伪造运行终态**：如果运行中途崩溃或缺少结束事件，只能标记为错误或未完成，严禁根据最后一条消息的内容去猜测或拼凑一个「已完成」状态。
- **禁止 WebSocket 断流后静默跳帧**：当客户端携带的序号（`seq`）或流标识（`stream_epoch`）与服务端补发窗口对不上时，服务端必须发送 `transcript.reset` 让前端重新拉取整页，严禁直接跳到最新位置继续发增量帧。
- **禁止静默降级兜底**：缺少必填配置、数据库状态非法或协议格式损坏时，必须在第一时间报错停止，不得带着残缺状态继续运行。
