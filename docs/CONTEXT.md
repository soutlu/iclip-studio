# iClip-Agent 领域概念与核心规则

本文定义 iClip-Agent 的核心业务概念、系统不变量与禁止的设计模式，前后端共同遵守。
- 日常开发命令见 [../AGENTS.md](../AGENTS.md)
- 系统架构与模块分工见 [architecture.md](architecture.md)
- 接口与跨端协议见 [../contract/conventions.md](../contract/conventions.md)
- 历史架构决策见 [adr/](adr/)

## 上下文

- **产品定位**：iClip-Agent 是一款 AI 视频创作工具。用户通过与 AI Agent 对话推进视频制作：从拆解参考视频、编写分镜脚本或导演工程文件，到生成分镜图片、视频片段，最终合成为完整成片。
- **系统组成**：
  - `web/`：前端网页应用。
  - `server/`：视频业务后端（浏览器唯一访问的入口）。
  - `runtime/`：独立的 Agent 运行时服务，在私有项目 Cue 里开发，本仓库按 `runtime.ref` 钉住的版本检出到这里（不进本仓库）；`plugins/video/` 是安装在运行时里的视频工具插件包。
  - `render/`：独立的成片渲染服务。
  - **存储与外部依赖**：业务数据与运行状态存储在 PostgreSQL，图片与音视频文件存储在对象存储（OSS）。企业登录与组织架构接入 SSO / PMS，商品款式目录读取外部只读 PDM 库，平台爆款视频数据由部署方导入，大模型与音视频生成调用外部 AI 服务。
- **前后端边界**：后端负责定义接口与权限规则（以 [../contract/openapi.json](../contract/openapi.json) 为准），前端根据生成的接口类型实现交互（详见 [../web/AGENTS.md](../web/AGENTS.md)）。

## 术语

术语分为两部分：
- **运行时概念**：Agent 运行时服务通用的一套概念。运行时本身只管跑 Agent，不管理具体的业务用户和权限；文中提到的管理权限（如 `agent:manage`）是视频后端在转发请求时检查的。
- **视频业务概念**：本产品特有的业务模型。其中对话、测试预览和运行上下文在底层对应运行时的会话数据。

---

### 一、 运行时概念

**应用（App）**
接入 Agent 运行时服务的业务后端（例如本产品的视频后端在运行时里登记为应用 `video`）。运行时信任接入的应用：当前操作的用户是谁、有没有权限访问某段对话，都由业务后端判断；运行时只负责校验应用的密钥，并原样记录后端传过来的用户 ID。新系统接入指南见运行时项目的 `docs/apps.md`。

**会话（Session）**
运行时用来承载一段对话的容器。消息记录、Agent 运行历史、界面展示的聊天记录（Transcript）以及工作区文件都挂在会话下。会话归创建它的应用所有，不同应用之间完全隔离；在本产品中，会话 ID 直接使用业务侧的对话 ID。

**运行目标（Run Target）**
一段对话绑定的顶层 Agent 及其固定版本。客户端只能选择用哪个 Agent，不能由前端直接指定底层模型或提示词：
- **创建时锁定版本**：用户新建对话时，只能选择首页公开、启用且已发布的 Agent。对话一旦创建，就会锁定该 Agent 当时的最新版本；后续管理员发布新版本、回滚旧版本或归档该 Agent，都不会影响已有对话。
- **分叉时的版本**：从旧对话分叉出新对话时，默认沿用源对话锁定的版本；如果分叉时切换了别的 Agent，则锁定新 Agent 当时的最新版本。
- **按次动态装配**：用户每发一条消息，系统按对话锁定的 Agent 版本去加载模型、提示词和插件，并读取所绑定技能的最新发布版、子 Agent 的当前发布版。如果该版本引用的模型已被停用或插件已被移除，仅这段对话会提示无法发送消息，不影响其他对话。

**工具（Tool）与工具集（Toolset）**
- **工具**：大模型在运行过程中可以调用的函数，包含名称、功能说明和参数定义。
- **工具集**：同一来源的一组工具。

**插件（Plugin）**
写在代码里的内置工具集，目前共有 6 个：
- `workspace`（读写工作区文件，内置在运行时中）
- `video`（理解视频内容）、`video_breakdown`（拆解参考视频）、`video_shots`（生成分镜表）、`shot_video`（视频抽帧与生成分镜图）、`iclip_studio`（校验导演工程文件）——这 5 个在视频插件包中。
- 插件之间可以声明依赖关系（例如启用 A 插件必须同时启用 B 插件），缺少依赖时无法发布或运行。
- 其中 `video` 插件调用的视觉理解模型直接固定在代码里，不随 Agent 配置改变；如果管理员没有在后台配置好对应的火山方舟模型，工具会直接报错并让 AI 提示用户联系管理员开启。

**MCP 服务（MCP Server）**
管理员（需 `agent:manage` 权限）在后台接入的外部远程工具服务，通过标准 MCP 协议（支持 Streamable HTTP 或 SSE）提供工具：
- **基本配置**：包含唯一标识（创建后不可改）、服务名称、服务地址、超时时间和自定义请求头。服务名称和地址不能与已有服务重复。
- **安全存储**：服务地址和请求头的值都会加密落库。管理接口会返回完整地址，但请求头的值在任何接口都只返回脱敏后的打码值（如 `••••abcd`）；编辑时如果不传某项，则保留原值。
- **使用自有账户（按用户登录）**：管理员可以把服务设成「使用自有账户」，每个用户在浏览器里经这个服务的标准 OAuth 登录**连接**一次，之后保持**已连接**；用户可以自己**断开**。服务拒绝续期时连接变成**连接已失效**，要**重新连接**；没连过是**未连接**。登录只能由发起的那个人完成，5 分钟内有效、只能用一次。服务不能自动注册客户端时，管理员要先填一个客户端 ID（与可选的密钥）。对话运行用发这条消息的用户自己的连接去调这个服务，管理员配的请求头与传输方式照常生效；用户没有能用的连接时，这次运行不提供这个服务的工具。测试连接用管理员自己的连接。
- **改设置影响已连接的用户**：改服务地址或关掉「使用自有账户」会断开所有人的连接；缩小权限范围会让拿到了更多权限的连接失效；换客户端 ID 会让用旧客户端连上的连接失效。会影响到已连接的用户时，保存前要管理员确认，并告诉他受影响的人数。
- **测试连接与挂载**：支持在保存前或保存后测试连接，连接成功后会拉取并保存该服务提供的工具列表。Agent 挂载该服务时，每个工具三种状态：**允许**（放给模型）、**要求审批**（放给模型，每次调用前要对话用户同意）、**关闭**（不放给模型）。新挂上的服务所有工具都是关闭；一个工具都不放时服务仍算挂载，但运行时不连它；早先存下的「全部工具」（包括服务以后新加的）照旧有效。模型看到的工具名会自动加上 `mcp_<服务标识>_` 前缀。如果运行时连不上该服务，当次对话运行会报错并指明是哪个服务不可用。
- **调用前审批**：顶层运行（包括测试预览）调到要求审批的工具时暂停，用户同意后才执行；拒绝则不执行，模型收到拒绝结果。子 Agent 的运行不能暂停等人，要求审批的工具不放给子 Agent。
- **删除与停用限制**：只要还有任何一个 Agent 的草稿或当前发布版本挂载了该 MCP 服务，就不允许停用或删除；删除服务时用户在它上面的连接一并删掉。

**技能库（Skill Library）**
供 Agent 按需加载的专业知识与操作指南库（仅 `agent:manage` 可见可管理）。每个技能由一份主文档 `SKILL.md`（开头 YAML 写明 `name` 和 `description`）以及 `references/` 目录下的多个参考文本文件组成：
- **标识与名称**：技能标识 `name` 全库唯一。标识和显示名称都属于技能本身的属性，修改后立即生效，不随版本回滚而改变；运行时加载或导出 zip 包时，都会自动把 `SKILL.md` 里的 `name` 替换成当前标识。
- **草稿编辑**：所有修改先在草稿上进行（支持增删改文件、重命名文件、从 zip 包导入覆盖草稿、或将历史版本恢复到草稿）。主文件 `SKILL.md` 不能删除或改名。修改单个文件时需带上读取时的内容哈希（`baseHash`），防止多人同时编辑互相覆盖。
- **发布版本**：校验草稿无误后可发布为不可变的新版本（版本号从 1 递增，可导出为 zip）。如果草稿内容与最新发布版完全一致，则不会重复发版。

**模型声明（Provider Declaration）**
随代码发布的「模型供应商接入规范」（每家供应商一份 YAML，服务启动时校验）。它规定了该供应商支持哪些接口协议（`responses`、`chat` 或 `gemini`）、配置密钥时需要填哪些字段、是否允许管理员手动添加自定义模型，以及默认内置哪些模型。
- 模型按 `(模型名, 类型)` 唯一区分，类型分为对话模型 `llm`、向量模型 `embedding` 和重排模型 `rerank`。
- `llm` 模型必须指定接口协议，并可配置上下文窗口大小和允许调节的思考档位（未配置则不支持调节思考深度）。
- 目前内置阿里云百炼、Google Gemini、OpenRouter、火山方舟与 OpenAI 兼容 5 份声明，其中百炼带有预置模型。

**供应商（Model Provider）**
管理员（需 `model:manage` 权限，默认仅 root 拥有）根据「模型声明」在后台实际接入的模型服务商：
- **模型管理**：内置模型默认启用，支持停用和重新启用，但不能修改属性或删除；如果声明允许自定义模型，管理员可以自行增删改模型。
- **权限隔离**：配置 Agent 的人员（持 `agent:manage`）只能看到已启用的供应商、已启用的对话模型和脱敏后的密钥名称，看不到明文密钥。
- **固定模型（写定的模型）**：系统中有三处功能不走 Agent 配置，而是直接在代码里指定了固定的火山方舟模型——**视频理解、参考视频拆解、资料库自动打标**。每次调用时，系统会自动寻找已启用、开启了该模型且配有默认密钥的火山方舟供应商；如果找不到可用配置，则直接返回「模型未启用」错误。所有密钥都保存在运行时服务内，业务后端通过运行时代理调用。

**密钥（Provider Credential）**
模型供应商的接入凭证（如 API Key 和接口地址），同一个供应商下可以配置多把密钥：
- **默认密钥**：添加的第一把密钥自动设为默认密钥；如果想删除默认密钥，必须先把默认切换到其他密钥。
- **加密与脱敏**：敏感字段加密存储，接口一律只返回打码后的值（`••••` 加后 4 位）。保存密钥时只检查必填项，不强制联网测试。
- **连通性测试**：支持在保存前用表单内容测试连接（调用该供应商第一个启用的 `llm` 模型发一条最小请求），也支持用已保存的密钥单独测试某一个具体模型。

**默认模型（Default Model）**
每种模型类型（如 `llm`）可以指定一个全局默认模型。`llm` 的默认模型用于为新对话自动生成标题；如果没设置默认模型，则不自动生成标题。被设为默认的模型不能停用或删除。

**Agent 标识、草稿与版本（Agent Config）**
- **Agent 标识（Agent ID）**：每个 Agent 的唯一英文代号（小写字母开头，仅含小写字母、数字和连字符，最长 40 字符，创建后不可修改）。Agent 还包含名称、功能描述（作为子 Agent 被调用时展示给主 Agent 看，修改立即生效）、是否在首页展示、排序位置以及归档状态。
- **草稿（Draft）**：正在编辑的 Agent 配置（包含系统提示词、所选模型与思考档位、挂载的插件、MCP 工具、子 Agent 以及按顺序绑定的技能）。保存草稿使用 `lockVersion` 乐观锁防止覆盖；草稿只检查基本格式，允许暂时不完整（例如还没选模型）。
- **版本（Version）与发布（Publish）**：点击发布时，系统会全面检查草稿中引用的模型、密钥、插件依赖、MCP 服务、技能和子 Agent 是否全部可用；如有问题会一次性返回所有错误字段位置。检查通过后生成不可变的新版本（从 1 递增）并设为**当前版本**。
- **引用保护**：只要某个技能、模型、密钥、供应商、MCP 服务或子 Agent 正在被任何一个 Agent 的**草稿或当前版本**使用，系统就会拦截对它的归档、停用或删除操作，并提示具体是哪个 Agent 在用（仅被历史旧版本引用则不拦截）。

**子 Agent（Sub-agent）**
主 Agent 可以将任务委派给其他已发布的 Agent 执行（可配置单次超时时间、最大调用次数和失败提示语）。**子 Agent 最多只允许一层嵌套**：作为子 Agent 的不能再挂载下一级子 Agent；反过来，已经挂载了子 Agent 的也不能被别人选为子 Agent。

**导出包（Agent Package）**
将某个主 Agent 及其所有子 Agent 的当前版本配置打包导出的 YAML 文件（自动剔除环境专属的密钥 ID）。导入时支持先预检（`dryRun`）再正式导入：如果存在同 ID 的 Agent 则只覆盖其草稿，不存在则新建草稿，导入后均不会自动发布。

**Agent 运行（Agent Run）与聊天记录（Transcript）**
- **Agent 运行**：大模型一次执行的底层持久化记录。注意：用户发一条消息（一轮对话 Turn），如果中途触发了人工审批并恢复执行，底层会产生多次运行（Run）。
- **模型上下文（Model Context）**：单次发给大模型的消息窗口。当对话过长触发「上下文压缩」时，系统会在历史中插入一条摘要分界线，后续只把「前文摘要 + 分界线之后的新消息」发给模型；但完整历史消息仍然保留，用户在界面上看到的聊天记录不会因为压缩而丢失。
- **Transcript**：把底层的运行记录转换成前端界面可直接渲染的树状结构：`轮（Turn，对应一条用户消息）→ 步（Step，对应一次模型回复）→ 块（Block，正文、思考过程、工具调用卡片等）`。协议详见 [../contract/conventions.md#5-agent-对话-transcript](../contract/conventions.md#5-agent-对话-transcript)。
- **对话用量（Conversation Usage）**：按对话和模型累计调用次数与 4 类 Token 消耗（普通输入、缓存命中、缓存写入、输出），包含子 Agent 的消耗；自动生成标题、上下文压缩摘要和视频理解工具的消耗不计入。

### 二、 视频业务概念

#### 1. 身份、角色与运行上下文

**主体（Principal）与双主体（Dual Principal）**
代表当前请求发起者的可信身份，包含所属用户、API Key 信息（如有）、最终生效的权限集合以及用户名。本系统的所有功能同时向「浏览器登录用户」和「携带 API Key 的机器调用方」开放，两者在后端解析为同一种 `Principal` 结构（详见 [../contract/conventions.md#2-双主体认证-dual-principals](../contract/conventions.md#2-双主体认证-dual-principals)）。

**API Key 与代指定用户操作（`users:act_as`）**
- **API Key**：挂在某个用户账号下的长期访问令牌（需 `api_keys:issue` 权限签发）。API Key 的权限在签发时明确勾选，不能超过签发人自己当时的权限，也不会随所属用户后续升职扩权而自动变大。
- **代指定用户操作（替人办事）**：拥有 `users:act_as` 权限的 API Key，在调用创建对话、需求单、发消息、提交生成或上传等写接口时，可以在请求体里传入 `user_name`。系统会将这次操作创建的数据直接归属到该用户名名下（如果该用户还没登录过系统，会自动创建一个同名占位账号，等本人日后通过企业 SSO 登录时自动认领）。此时操作权限仍按该 API Key 自身的权限判断，审计日志记录为 `目标用户名#Key名称`。没有 `users:act_as` 权限的 Key 传 `user_name` 仅作为传给上游供应商的对账标签，不会切换数据归属。

**角色（Role）**
一组权限的打包名称，用户的最终权限 = `所拥有的角色权限并集 ∪ 单独勾选的直接权限`（定义见 [rbac.py](../server/src/iclip/domains/identity/rbac.py)）。**防越权原则**：管理员在修改其他用户时，不能管理权限比自己更多的人，也不能给别人赋予自己没有的权限。

**运行依赖（Run Deps）**
Agent 运行期间携带的上下文信息（包含对话所属用户 ID、对话 ID、是否为测试预览、以及上游对账用的 `user_name`）。Agent 工具在执行需要权限的操作时，每次都会根据所属用户 ID 实时查询该用户当前的最新角色权限（不使用发消息时那把 API Key 的权限）。

#### 2. 对话、测试预览与制作流程

**对话（Conversation）**
用户在界面上进行一次视频创作的聊天窗口，工作区文件按对话严格隔离：
- **可见性与软删除**：普通用户只能看到自己未删除的对话；删除对话只是做软删除标记（俗称「墓碑」），底层的运行记录、工作区文件和生成视频都会保留，且已删除的对话禁止再做任何修改。拥有 `users:manage` 权限的治理者可以查看和复盘全站所有人的对话（包括已删除的对话），但不能修改别人的对话。
- **关联需求单与合集**：一段对话最多可以关联 1 张创作需求单和 1 个对话合集，两者随时可以绑定或解绑。
- **分叉（Fork）**：任何能看到这段对话的人（包括治理者查看已删除的对话），都可以从任意一轮对话处「分叉」出一段属于自己的新对话。新对话会复制源对话截至那一轮的聊天记录和当时的工作区文件；源对话之前生成的视频不会复制一份新数据，而是通过**继承关系**让新对话直接可见可用（见下文「继承」）。分叉出的副本不计入审计报表。
- **做同款**：在资料库看到任意一张带有工程文件（`film.icml`）或分镜文件（`video_shot.json`）的素材卡时，即使没有源对话的访问权限，也可以一键「做同款」——系统会把源对话的几份制作文件复制到一段全新的空白对话中，供 AI 导演在此基础上改写新片（不复制聊天历史，也不继承原视频）。
- **四个独立状态维度**：
  1. **是否在跑（`busy`）**：当前是否有对话轮次正在执行（等待人工审批或回答问题时也算 `busy`）。
  2. **人工交互（`pendingInteraction`）**：是否卡在等待审批（`approval`）或提问（`question`）。
  3. **上轮结局（`lastTurnReason`）**：最近一轮是正常完成（`completed`）、失败（`failed`）还是被中止（`aborted`）。
  4. **视频生成进度**：该对话下是否有视频（出片、编辑段、合成）正在排队或生成中（`none / queued / running`）。注意：后台生成视频不占用对话轮次，不算对话 `busy`。
- **已收尾标记**：由对话创建者手动点击标记「已收尾」；一旦创建者继续发消息或提交新的视频生成，系统会自动取消该收尾标记（识别字幕、生成配乐、导出成片不会取消收尾标记）。

**测试预览（Agent Preview）**
供管理员（持 `agent:manage`）在后台编辑 Agent 时直接试聊草稿或某个历史版本的专用通道：
- **与正式对话完全隔离**：不出现在对话列表、侧边栏、统计和审计报表中，不支持分叉或做同款，预览中生成的图片也不关联对话 ID。
- **实时加载草稿**：预览草稿时，每发一条消息都会读取那一刻最新保存的草稿配置（所绑定的技能取最新发布版、子 Agent 取当前版本）。
- **严格私有**：一段预览只有发起人自己（且当前仍保有 `agent:manage` 权限）能看到和使用，**连全站治理者也看不到别人的测试预览**。每个人在每个 Agent 下只保留一段当前预览，开启新预览会自动中断并替换旧预览。

**合集（Collection）**
用户用来整理自己对话的文件夹。普通用户只能管理自己的合集；治理者可以查看、改名或删除所有人的合集。

**媒体地址（Media Address）**
工具与制作页收到的图片或视频地址，一律按完整 URL 原样使用，不看它从哪来（对话里没出现过的、别的工具给的都一样）。地址对不对只在提交时检查，读取时不查：
- **提交时检查**：交付镜头组表、检查工程文件、按节点生图、出镜头帧、拆解视频，以及在制作页上插入图片、选用图片、生图与出片时，用到的每个地址都必须链接能打开且类型正确（图片就是图片，视频就是视频）。
- **读取时不查**：读图、打开制作页、视频理解以及取帧时下载视频，都不预先检查地址；取不到时由取的那一步如实报错。
- **检查不过时**：链接打不开（失败会自动再试一次）或类型不对，就按位置报出是哪一个，原因只说「打不开」或「不是图片」「不是视频」，由模型或用户换一个地址。
- **出网安全**：由实际去取地址的那一方负责（机制见 [architecture.md](architecture.md)）。

**镜头组（Shot Group）**
分镜脚本（`video_shot.json`）中的基本单元，直接用从 1 开始的**镜号**（`shots[].index`）标识身份：
- **镜头帧**：镜头组里引用的第 N 张参考图，在提示词正文中用 `@ImageN` 引用。
- **版本组**：一段对话下的所有可用视频（含分叉继承来的视频）按镜号分组，组内按生成完成时间自动编号为 `V1, V2...`，方便用户在多版生成结果和剪辑合成结果之间切换对比。

**导演工程文件（Film Project）与制作页（Film Page）**
AI 导演制作短片时维护的一对工作区文件，以及用户在前端对应的可视化编辑页面（接口细节见 [../contract/conventions.md#6-对话-conversations](../contract/conventions.md#6-对话-conversations)）：
- **内容文件 `film.icml`**：定义全片的人物/场景/道具设定、配音音色、拍摄手法、剧本台词（`<script>`），以及每个生图节点和视频分段请求的参数与参考图列表。节点正文通过 `@Image1..N` 引用该节点参考图列表中的图片；如果列表中有任何一张参考图还没选好图片，系统会禁止生成该图片或该组视频。
- **运行文件 `film.icrun`**：记录所有候选图片的 URL，并用 `use` 语句指明每个生图节点当前最终选用了哪一张图片。注意：生成了一张新图片只相当于多了一个候选版本，必须写入 `film.icrun` 选用后才算正式生效。
- **制作页交互**：将上述两个文件渲染成直观的分镜卡片。用户可以在页面上直接修改描述文字和台词、增删单组视频引用的参考图、选用或更换图片、一键切换全片画幅比例，也可以直接在页面上点击生成某张设定图或某组视频。所有修改在校验通过后会自动同步写回工程文件。
- **制作页的图片地址**：插入或选用的图片只要链接能打开、确实是图片就行，不限来源（见「媒体地址」）。打开页面时只检查两个文件的结构、不检查地址，写着打不开的图在页面上就是一张打不开的缩略图，到生成时才会被拦下；生图与出片在受理前检查这次要用的参考图。

**成片草稿（Whole-film Draft）与成片导出（Whole-film Export）**
- **成片草稿**：每段对话拥有一份保存在服务端的成片文件（时长没有上限，通过版本号乐观锁整份保存）。成片文件是一份 HTML：时间线上每个片段是文件里的一个标签，写着它从几秒到几秒、在第几行、用什么；文件不带脚本。片段有三种：
  - **视频片段**：本对话（或分叉继承）的一段素材片，可以调增益、速度、起始位置（从素材的第几秒放起），声音可以淡入淡出，也可以静音（画面照常出现，只是不出声）。加进成片时确认素材片有声音才写成有声音，素材片没有声音、读不出有没有声音时都写成静音；素材片没有声音的视频片段不能取消静音。
  - **放着组件或块的片段**：组件库里的一个条目（组件或块），带着它的可填项取值，可以从条目自己的某一秒开始播。条目没有固定尺寸、或者和画面一样大时铺满画面；固定尺寸和画面不一样大时按原比例缩到放得下，居中。字体类可填项取到的字体（没填用条目给的默认字体）用在条目的标题和正文上，中文退到成片的中文字体。
  - **音频片段**：本对话（或分叉继承）的一条已完成的音频记录（生成的背景音乐，或关联到本对话的音频上传），可以调增益、速度、起始位置、淡入淡出，音频比片段短时可以循环播。

  视频片段和音频片段的素材地址写在片段上，并绑到按生成记录编号取名的变量。增益最多加 12 dB；速度在 0.1 到 10 倍之间，改速度不改片段在时间线上的长度，片段用掉的素材是片段长乘速度，所以片段最长只能拉到「素材剩下的长度 ÷ 速度」。成片总长是所有片段里最晚的结尾。时间线分两个区：画面区（视频片段和组件或块的片段）在上，声音区（音频片段）在下，两个区的行号各算各的。行号只管片段显示在区里的哪一行（行号小的在上面），同一个区同一行的片段不能时间重叠；编辑器里片段只能在自己的区里挪动和新开一行，新开一行时只有同一个区里下面的行往后顺延；画面区最上面那一行是主轨，波纹删除时补位、没指定位置的镜头接在末尾，都在这一行。画面区不同行的片段同时出现时，谁盖住谁看片段上的叠放顺序，大的在上面，一样大时文件里写在后面的在上面。编辑器新加的片段叠在最上面；换行时只重排被挪的那个片段：往上挪就抬到它压着的、时间上重叠的片段之上，往下挪就降到盖着它的片段之下（不低于 0），别的片段不动。片段可以标成隐藏：仍留在时间线上、占着它的时间，预览和导出里都不出现也不出声（隐藏的音频片段就是静音）；编辑器按行隐藏和显示，声音区的行叫静音和取消静音（一行的片段全隐藏了，这一行才算隐藏），也可以在右侧栏隐藏或静音选中的那一个片段；片段换到别的行时带着自己的隐藏标记。
- **成片导出**：将当前成片文件交给独立的渲染服务（`render/`）渲染为最终 MP4 视频（按先进先出顺序单任务渲染，超时上限 6 小时）。导出完成后生成长期有效的公开下载链接。详见 [../contract/conventions.md#成片草稿](../contract/conventions.md#成片草稿)。

#### 3. 媒体生成任务、资料库与标签

**生成任务（Generation Job）**
只要调用了生成模型，或者在对象存储中产出了受管媒体文件，系统都会在数据库里记录一条生成任务。
- **素材片**：指已经生成完成、可以完整播放的**出片（原始生成视频）**或**合成视频（剪辑拼接后的视频）**。局部替换用的「编辑段」、「导出的成片」和「超分高清版」都不是素材片。
- **10 种生成记录类型对比**：

| 记录类型 | `kind` | `operation` | 来源 `source_job_id` | 原作 `root_job_id` | 关联对话 | 取消对话已收尾状态 | 计入对话视频生成进度 | 进入全站资料库 | 计入审计报表 |
|---|---|---|---|---|---|---|---|---|---|
| **出片**（素材片） | `video` | `generate` | 无 | 无 | 可选 | 是 | 是 | 成片素材 | 是（有镜号且关联对话） |
| **编辑段**（局部重绘） | `video` | `generate` | 基底素材片 | 最初出片 | 可选 | 是 | 是 | 否 | 否 |
| **合成**（素材片） | `video` | `compose` | 基底素材片 | 最初出片 | 可选 | 是 | 是 | 成片素材 | 否 |
| **文生图 / 帧图编辑** | `image` | `generate` | 无 / 底图记录 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **宫格切图** | `image` | `cut` | 宫格原图记录 | 无 | 可选 | 否 | 否 | 否 | 否 |
| **用户上传** | `image`/`video`/`audio` | `upload` | 无 | 无 | 仅音乐可选 | 否 | 否 | 否 | 否 |
| **字幕识别记录** | `subtitle` | `generate` | 被识别的素材片 | 无 | 随素材片/请求 | 否 | 否 | 否 | 否 |
| **生成背景音乐** | `audio` | `generate` | 无 | 无 | 必填 | 否 | 否 | 否 | 否 |
| **成片导出记录** | `whole_film` | `render` | 无 | 无 | 必填 | 否 | 否 | 成片 | 否 |
| **高清版（超分）** | `video` | `enhance` | 素材片或成片 | 无 | 否 | 否 | 否 | 否 | 否 |

- **核心规则**：
  - **不自动重试**：所有付费生成任务一旦失败即为终态，后台绝不自动重新提交（见不变量 10）。
  - **两层血缘（来源与原作）**：对视频做局部重绘（编辑段）或剪辑拼接（合成）时，`source_job_id` 指向直接基于的那一版素材片，而 `root_job_id` 始终指向最源头的那条原始出片，方便一键拉出整条修改链。
  - **自动识别字幕**：每当一条素材片生成完成，后台会自动创建一个字幕识别任务（若動画无音轨或无人说话，识别正常完成、结果为空列表）。
  - **超分高清版全站共享**：任何人都可以对素材片或成片发起超分（提升到更高分辨率）；同一源视频的同一清晰度全站只保留一条未失败的记录，大家共用。

**继承（Inherited Records）**
对话分叉后，新对话对源对话（及更早祖先对话）已有出片记录的**只读引用关系**：
- 新对话可以直接看到、下载源对话在分叉时刻之前已经完成的视频，也可以拿它们当基底继续剪辑或修图，但不能对继承来的旧轮次点「重新生成」。
- 视频的原始归属人和所属对话保持不变。

**生成结果（Generation Output）**
- **图片与背景音乐**：上游模型返回的临时链接必须由服务端下载处理（音乐会去除首尾静音并统一响度）后，转存为本系统对象存储的永久公开链接才算成功；转存失败则整个任务记为失败。
- **视频**：上游生成的视频必须同时具备「无水印原片」和「带水印预览片」两个稳定地址才算成功；本地合成视频与导出成片直接存入对象存储，无水印版。

**上传（Upload）**
用户通过前端直传文件到对象存储（先签名 `sign`，传完后确认 `confirm`），或发消息时由服务端自动下载外部图片转存：
- **视频按 MD5 去重**：不同用户上传完全相同的视频文件时，对象存储只保留最早那一份文件地址，但仍会为每次上传各自记录一条上传记录。图片与音频不去重。
- 音频上传确认时可以关联到自己的某段对话，供该对话的成片草稿作为背景音乐使用。

**资料库（Library）**
面向全站用户（持 `generation:read` 权限）开放的创作成果与素材复用中心，包含 4 个板块：
1. **成片素材（素材卡）**：以对话为单位聚合展示全站生成的素材片（按镜头组和版本排列，即使原对话已被删除也照常展示）。如果该对话包含工程文件或分镜文件，任何浏览者都可以直接点击**「做同款」**。
2. **灵感库（参考视频，Reference Video）**：按视频 URL 唯一记录的外部参考视频及其 AI 拆解报告（Markdown）与分类标签。无论是用户在资料库直接上传，还是 Agent 在对话里拆解，都会沉淀到这里共享。只有首次上传/拆解的创建者（或治理者）可以修改拆解报告、重拆、移除，或用拆解内容发起**试生成**（验证拆解还原度）。
3. **爆款素材库（Hit Case）**：从「成片素材」中精选出来的优秀单版视频（要求所属对话的工作区里有新片执行方案 `treatment.md`）。入选后系统会自动读取 `treatment.md` 进行 AI 打标。
4. **成片（成片卡）**：按对话聚合展示全站已导出的完整成片视频（包含历史导出版本 `V1, V2...`），支持搜索标题与下载。

**标签（Library Tag）**
灵感库和爆款素材库共用的一套分类标签树（顶层为「维度」，维度下最多支持 3 级标签值，由管理员动态配置）：
- **AI 自动打标 vs 人工打标**：每个维度可配置是否开启 `auto_fill: ai`。当参考视频拆解完成或爆款素材入选时，后台会让大模型读取拆解报告或 `treatment.md`，自动勾选所有 AI 维度的标签（整组覆盖 AI 维度，但绝不改动人工维度的标签）。打标进行中禁止手动改标。
- **筛选逻辑**：同一维度下勾选多个标签为「或（OR）」关系（勾选父标签会自动包含所有子标签），不同维度之间为「且（AND）」关系。

**品牌模板（Brand Template）**
管理员上传维护的品牌专属字体文件（静态 TTF/OTF，服务端自动解析字族、字重和字符集覆盖范围，只停用不删除），供成片渲染与字幕使用。

#### 4. 创作需求单、外部商品库与审计统计

**创作需求单（Task）**
派发视频创作任务的工单（包含视频规格、1～20 款商品信息快照、分类参考素材和创作要求，持 `tasks:read` 全站可见）：
- **生命周期**：`草稿（draft）→ 已下发（published）→ 已认领（confirmed）→ 已撤回（withdrawn，终态）`。草稿仅创建者或治理者可改可删；下发后商品列表与核心视频规格将被冻结不可修改。
- **多人认领与自动认领**：一张需求单可被多人认领；**只要用户把自己的某段对话关联到某张已下发的需求单上，系统就会自动将该用户记为该需求单的认领人**。详见 [../contract/conventions.md#8-创作需求单-tasks](../contract/conventions.md#8-创作需求单-tasks)。

**PDM 款目录与爆款视频（Inspiration Video）**
- **PDM 款目录**：连接外部只读商品库，仅用于查询商品款号对应的「品牌」和「品类」编码。
- **爆款视频**：部署方导入的历史高表现带货视频库。按款号检索时，如果该款自身没有爆款视频，系统会自动按「同款 → 同品牌同类目 → 同类目」三级回退寻找替身视频。

**埋点事件（Tracking Event）**
前端上报的用户行为记录（目前仅有视频下载事件 `video.downloaded`）。一次成功的下载记一条事件，`jobId` 是实际下载的那个文件的记录（素材片、编辑段、高清版或成片），下载失败不记。功劳算给谁不在上报时决定，由「视频生成报表」按血缘在读取时计算。

**审计口径（Audit Metrics）**
供治理者查看团队产能、一次通过率、耗时与 Token 消耗的统一统计标准（**分叉出的对话副本、局部编辑段、合成视频、无镜号或未挂对话的视频均不计入产能**）：
- **出片件数（Deliveries）**：有成功出片的需求单算 1 件；没挂需求单但有成功出片的独立对话也算 1 件。
- **镜数与一次通过率**：同一对话下的同一个镜号只要成功生成过至少 1 条视频，就算 1「镜」。如果该镜只成功生成了 1 次就定稿（中间失败过不算，成功后又重新生成则不算），称为**一次通过**。
- **有效镜与有效率**：只要某镜生成的视频被下载过至少 1 次，该镜就算**有效镜**，`有效率 = 有效镜数 ÷ 总镜数`。下载由它产生的编辑段、合成、成片和高清版，都算它被下载过，口径与视频生成报表相同。
- **视频生成报表**：只读视图 `iclip.video_generation_report` 供数据分析直接查询，每行一条成功或失败的出片，编辑段不单独成行。「是否下载」不限下载人：出片本身之外，还算由它产生的编辑段、合成、成片和高清版。
- **废片时长**：同一镜如果成功生成了多条视频，除了最后完成的那一条外，其余早期成功视频都算**废片**，统计其总时长。
- **交付周期与单任务有效时长**：从对话首次运行到最后一条视频完成的总跨度为「交付周期」；其中剔除超过 30 分钟的闲置空档后、真正有 Agent 运行或视频生成的累计时段称为「单任务时长」。
- **四类任务执行异常**：系统自动在对话执行记录上标记 4 种异常——`反复重试`（单镜成功生成 ≥ 3 次）、`视频悬挂`（提交上游超过 1 小时仍未返回结果）、`消耗离群`（单对话 Token 消耗超过当期平均每件出片消耗的 3 倍）、`需求单卡住`（需求单关联了 ≥ 3 段对话尝试却始终零出片）。

## 不变量

每一条代码路径都必须严格遵守以下 12 条底线规则：

1. **PostgreSQL 是唯一的持久化事实源。** 进程内存不能用来承担跨进程的业务正确性；前端的实时流投影和内存缓存都只是派生视图。
2. **可信身份只来自入口建立的 `Principal`。** 每个请求只在入口中间件解析一次登录态或 API Key；下游业务代码严禁自行解码凭证或轻信客户端传来的 `userId` / `role`。唯有持有 `users:act_as` 的 API Key 可以在指定的 6 个写接口入口按 `user_name` 切换一次归属用户。
3. **权限集合是唯一的授权依据。** 已过期、已吊销或所属账号已停用的 API Key 必须直接拒绝，绝不能回退使用所属用户的个人权限。
4. **API Key 的操作必须全程可审计。** 数据库记录与 OSS 对象元数据都必须同时保留「实际归属用户」与「调用方 API Key 身份」，在异步排队或子 Agent 运行中不得丢失。
5. **敏感凭证绝不进代码与配置文件。** 所有密码、Token 和密钥只从环境变量读取；必填环境变量缺失或为空白字符串时，服务必须在启动阶段直接报错退出并指明变量名。
6. **运行生命周期由数据库驱动。** 消息入队、运行状态流转、崩溃恢复与审批续跑一律以数据库记录为准；浏览器断开 WebSocket 只取消消息订阅，不会中止后台正在运行的任务。
7. **Agent 运行配置只有一个事实源。** 首页可选 Agent 列表、对话锁定的版本、挂载的插件/技能与模型配置全部从运行时数据库派生，不再读取本地静态 YAML 配置。
8. **客户端生成的 ID 仅作幂等键，绝不决定数据归属。** 消息 `prompt_id`、对话 `id` 与需求单 `id` 支持客户端生成以实现重试幂等；如果与系统中其他用户的记录 ID 撞车，一律按不可见返回 `404`。
9. **「看不看得见」与「能不能改」分开判断。** 无权查看的资源统一返回 `404`（不暴露该资源是否存在）；有权查看但无权修改的资源明确返回 `403`。治理者的全局查看权限绝不自动变成修改权限。详见 [../contract/conventions.md#4-错误处理与响应信封](../contract/conventions.md#4-错误处理与响应信封)。
10. **付费生成任务一旦提交，后台绝不自动重试或擅自篡改参数。** 如果请求发给上游后超时、不确定上游是否已受理计费，必须明确标记为失败，不能盲目重投。是否重新发起一次付费生成由调用方策略决定（例如分镜出图工具配置了「先试 dev 渠道、失败再起一个新任务试 pro 渠道」，属于显式新建任务）。
11. **发给模型的媒体必须保留原始标识，工具产出的媒体必须可追溯。** 传给大模型的图片/视频必须带有包含原始 URL 和类型的媒体标签（见运行时项目的 `src/agent_runtime/harness/media.py`）；工具产出的媒体地址必须通过返回值或工作区文件交给模型。
12. **上下文压缩只缩短发给模型的窗口，不删除历史记录。** 压缩摘要边界与原始消息共同保存在数据库中，界面展示的历史轮次不受压缩影响。

## 禁止逻辑

以下设计模式在系统中被明确禁止，不得以「临时方案」名义引入：

- **禁止信任客户端传来的身份字段**：除 `users:act_as` 专用入口外，严禁读取请求体、Query 或普通 Header 中的 `userId`、`tenantId`、`role` 作为鉴权依据。
- **禁止让 API Key 权限随用户角色自动膨胀**：API Key 只有创建时显式勾选的权限，需要新权限必须重新签发。
- **禁止伪造运行终态**：如果运行中途崩溃或缺少结束事件，只能标记为错误或未完成，严禁根据最后一条消息的内容去猜测或拼凑一个「已完成」状态。
- **禁止 WebSocket 断流后静默跳帧**：当客户端携带的序号（`seq`）或流标识（`stream_epoch`）与服务端补发窗口对不上时，服务端必须发送 `transcript.reset` 让前端重新拉取整页，严禁直接跳到最新位置继续发增量帧。
- **禁止静默降级兜底**：缺少必填配置、数据库状态非法或协议格式损坏时，必须在第一时间报错停止，不得带着残缺状态继续运行。
