# iclip-agent 领域锚点

本文是 Productor 视频创作产品的领域锚点：上下文（产品与系统的背景事实）、术语（产品赖以工作的持久事实与瞬态信号）、不变量（每条代码路径都必须成立的规则）、禁止逻辑（被刻意设计掉的推理模式）。

本文只登记已落地的领域真理——术语与不变量随实现进入本文，未实现的部分不进本文。命令与门禁见 [../AGENTS.md](../AGENTS.md)；机制见 [architecture.md](architecture.md)；技术方案的选择与权衡见 [adr/](adr/)。

## 上下文

- **产品**：Productor 是 AI 视频创作产品。用户在项目中与 AI agent 对话推进创作：从参考素材拆解，到镜头 prompt 表，再到镜头帧与媒体生成。
- **系统**：`web/`（React SPA，同源 `/api` 直连后端）+ `server/`（FastAPI 模块化单体）+ Postgres（唯一事实源）+ Redis（只放在途与近期的运行事件流）。外部依赖：企业 SSO 与 PMS（企业身份与部门资料）、LLM 引擎（PydanticAI）。
- **`web/` 的角色**：**历史前端代码，只读留存**——既不是需求来源，也不是合同事实源，方案与实现都不参考它；产品行为与对外合同一律由后端定义（见 [../contract/](../contract/) 目录）。

## 术语

**主体（Principal）**：
一次请求的唯一可信身份：`kind ∈ {user, api_key}`、`user_id`（key 也归属用户）、`api_key_id?`、生效权限集。由宿主的 PrincipalResolver 每 hop 解析一次，下游一切只消费它。
_不是_：客户端提交的任何身份字段、可在下游二次解码的 token、两套并行的用户/机器身份模型。

**API Key**：
`iclip_sk_` 前缀的长期凭证，归属某个用户；服务端只存 SHA-256 哈希与展示前缀，明文仅创建响应出现一次。key 的有效权限就是**显式授予集**（签发时校验 ⊆ 签发者当下权限；签发权 `api_keys:issue` 仅 root 角色持有）。
_不是_：角色的镜像、独立账号体系、可查回明文的凭证。

**角色（Role）**：
权限集合的命名快捷方式，代码内预置（root/editor/viewer），无角色管理表。用户有效权限 = 所分配角色的权限并集 ∪ 直接授权。
_不是_：身份等级体系、可动态定义的实体、第二套授权机制。

**双主体（Dual Principal）**：
同一套产品能力对两类调用方开放：浏览器用户（HttpOnly cookie `iclip_session`）与机器调用方（`Authorization: Bearer iclip_sk_...`）。两者解析为同一 Principal 类型，权限词汇表相同。
_不是_：两套 API、两套权限系统、为机器单开的旁路。

**运行目标（Run Target）**：
承载一个 agent 运行的顶层 Agent，由声明式配置定义（官方 spec × prompt 资产 × 能力声明 × 下属声明），启动期装配冻结、运行期按 id 读取。id 是唯一权威身份：它同时是 URL 里的 `{agent_id}`，并被强制覆盖成 agent 的 `name`。
_不是_：模型配置本身、客户端可指定的东西、可在运行期改写的选择。

**对话（Conversation）**：
用户在界面上看到的一个聊天窗口：有归属、有名字、能改名能删。它的 id 由**服务端**发放，客户端拿它当 AG-UI 的 `threadId` 用；一段对话下有很多次运行，运行按它归档，agent 的工作区也按它划地盘。删掉一段对话，agent 在里面写下的工作区文件一并删掉；运行记录留着（那是账本）。
_不是_：客户端自己编一个字符串就能凭空成立的东西（发消息时服务端核对，对不上一律当作不存在）、cookie 会话、消息历史的容器（历史目前由客户端每次带上来）。

**Agent 运行（Agent Run）**：
一次 agent 执行的持久事实：血缘（自身、所属对话、父运行）、逐步事件、可续跑的消息历史快照、工具副作用状态，全部落 Postgres。续跑与恢复靠读库。
_不是_：进程内存里的会话对象、worker 内存缓冲、可由客户端提交或改写的数据。

**运行依赖（Run Deps）**：
一次运行携带的可信身份，就是发起它的那个主体。运行发起时捕获一次并随运行冻结（跑到一半吊销不中断它），下属运行自动继承同一个。工具的授权与审计只认它。
_不是_：装配期挂在 agent 上的东西（注册表跨运行共享，挂上去就串人）、服务与连接的容器（那些在装配期由组合根注入）、客户端可写入的对象（客户端提交的 state 一律不消费）。

**对话素材（Conversation Material）**：
模型能交给工具的地址：这次运行的**模型请求那一侧**（用户消息、工具结果、agent 指令）逐字出现过的媒体地址。用户发的附件带着 tag，种类是明写的；工具产出的地址是裸的，只知道它确凿来自本对话。工具按自己的代价挑：要下载整片、要花钱出图的一律要求「出现过，且声明过种类的种类得对」。
_不是_：一张登记表或一张库表（消息列表本身就是那张表）、安全边界（工作区是模型可写的，写进去再读回来就绕过了；防 SSRF 得在出网取素材那一层单独做）、模型自己写下的地址（响应侧一律不算，算了就等于自己给自己发通行证）。

**运行事件流（Run Stream）**：
一次运行对外吐出的事件序列，按顺序存在 Redis 里，每帧带着自己在流中的位置。运行在后台跑，事件只往流里写；谁想看就来订阅，可以从任意位置接着读。流的名字里带着归属（谁的、哪段对话的运行），因此客户端自己起的运行 id 只是它自己那一摊里的一个名字——猜别人的落不到别人的流上，同一个 id 换一段对话也不会串到一起。运行结束后流还留一段重放窗口，过期即整条消失。
_不是_：事实源（持久事实只在 Postgres）、消息历史（那是快照）、绑在某次 HTTP 请求上的响应体、可跨用户寻址的东西。

**生成任务（Generation Job）**：
一次媒体生成的持久事实：谁发起的（含哪把 key）、生成什么（有类型的请求参数，含用哪个模型 / 走哪个渠道）、走到哪一步、结果在哪。**这张表只有事实，没有排期**——「几点该做它、试了几次、谁在做」在任务队列自己的表里，清空那些只丢排期不丢事实。受理时不碰外部接口；推进它的是后台，与任何一次 HTTP 请求无关。
_不是_：内存或 Redis 里的待办项、绑在某次请求上的同步调用、外部接口状态的镜像（provider 的状态字符串原样存着，不映射成自己的枚举）。

**生成结果（Generation Output）**：
一次成功生成对外给出的那个地址。图片的结果转存成本系统自己的公开对象后才算数（provider 给的是会过期的签名 URL）；视频目前直接是 provider 的地址。
_不是_：会过期的签名链接（图片）、provider 原始响应（那是排障快照，不对外）。

**产品资料（Product）**：
一个款在 PDM 里的资料快照：款号、状态、品牌、品类、颜色和产品图。它**不是我们的事实**——数据在外部一个只读库里（PDM 经 CDC 同步过来的副本），我们按款号读一次就走，不落库、不缓存、不改写。上游只给裸码（品牌 `"2"`、品类 `52`），翻成人话的对照表冻在本仓代码里；**查不到的码名字留空，绝不猜**。款还带着一个 WMS 编号，那是同一个款在另一套系统里的名字，和 PDM 款号不通用。
_不是_：本系统的实体（没有产品表，也不该有）、可写的东西、素材账本里的条目（图片地址只是给人看的，要进账本得另外转存）。

**创作需求单（Task）**：
一份被记录在案的视频创作要求：谁提的、要做什么、什么时候要、走到哪一步。它是**全公司都看得见的一张工作队列**——没有属主，只有创建者。草稿阶段是提需求那个人的私事（只有他与治理者能改能删）；一旦下发，需求方写下的创作输入就冻结，之后能改的只剩管理信息与接单之后才补得出的那几项（时长、画幅、需求描述、参考素材）。接单与撤回任何有写权限的人都能做；撤回是终态，不回到下发。
_不是_：私人资源（不做归属过滤，「别人的一律 404」那套在这里不适用——看得见但不让改是 403）、生成任务（那是一次媒体生成的排队事实）、可以删掉的历史（下发之后只能撤回，撤回留痕、删除不留）。

**爆款视频（Inspiration Video）**：
自家款在平台上跑出成绩的那些短视频，连同它的表现指标、CT 归属与平台类目。它**不是我们的事实**——数据在外部一个只读库里（数仓的爆款榜），我们按款查一次就走。**按款查用的是 WMS 编号，不是 PDM 款号**：两套编码不通用，传错的失效是静默的（返回空列表）。排序与截断都在库里做，因为换一个排序维度换的是一批样本，不是同一批的重排。
_不是_：本系统的实体、素材账本里的条目（视频地址只是给人看和挑的，要进账本得另外转存）、可由综合分排序的东西（哪个维度算「爆」是调用方的判断）。

## 不变量

每条代码路径都必须成立；能机械守卫的由门禁强制（[../AGENTS.md](../AGENTS.md) §4「机械护栏」）。破坏任何一条都是设计变更，须显式决策。

1. **Postgres 是唯一持久化事实源。** 业务事实、agent 运行与消息历史都落 Postgres；worker 进程内存只承载当前连接、当前 run 或性能缓存，绝不承载跨 worker 正确性。Redis 只承载在途与近期的运行事件流：它可以整段丢掉而不损失任何事实（代价是那次运行的事件接不回来了，客户端重新发起），因此不构成第二个事实源。
2. **可信身份只来自宿主建立的唯一 `Principal`。** PrincipalResolver 每 hop 只解析一次（cookie 验签一次 / key 哈希查表一次 + 活跃属主加载一次），写入 `request.state.principal`；下游不得再解码 token、查询用户或消费客户端身份字段。Principal 解析与传输无关：HTTP 中间件、WS 握手（cookie + Origin 校验）与 Bearer 头共用同一解析器。
3. **权限集合是唯一授权货币。** 用户有效权限 = 角色权限并集 ∪ 直接授权；API key 有效权限 = key 显式授权集。签发需 `api_keys:issue`（仅 root），签发时校验授予集 ⊆ 签发者当下权限；过期、吊销或属主停用的 key 一律 401。
4. **key 行为可审计。** 所有事实行记录 `user_id + api_key_id?`——谁的 key 干的，永远可追。
5. **地址与密钥只存在于环境变量。** 配置 YAML 只有形状，一个地址一个凭证都不进仓——公开仓不该说清我们在调谁的哪个接口。运行必需的变量在 bootstrap 阶段一次全报出来（报变量名）；空串与空白等于没设；API key 只存哈希。
6. **run 生命周期由数据库持有。** 没有自定义 pending 运行时、没有本地 run 队列；运行事实先落库，恢复与续跑一律读库。运行也不由某次 HTTP 请求持有：客户端断开只结束订阅，不取消运行。
7. **运行目标只有一个声明事实源。** 配置声明 → 装配期冻结；路由、白名单、能力挂载都从它派生，不得各自重建平行映射。
8. **客户端铸造的 id 只做幂等键，服务端发放的 id 才做身份。** 运行 id 必须由客户端在发起之前铸造：它要在副作用发生之前就知道这次运行叫什么，否则连接在响应到达前断掉，那次运行就没人认领了（钱花了、接不回来、重试还会再跑一次）。反过来，会话 id 必须由服务端发放：会话是记录在案的事实，「存在」这件事不能由客户端说了算。
9. **行级归属语义**：不可见资源返回 `NotFound`（不泄露存在性），可见但禁止才是 `PermissionDenied`；manager 视角不加 owner 过滤。
10. **付费的外部调用不自动重投、也不替调用方换参数。** 视频与图片生成接口都没有幂等键，一次成功调用就是一次计费。所以调用前先落「正在提交」，「不知道上次发出去没有」的行只能判失败并说清原因，由人决定要不要重来。**用哪个模型、走哪个渠道一律由请求带来**（不同取值价钱不同，替调用方偷偷换一个等于悄悄改了这次花多少钱，与悄悄重投同类）；失败就把失败照实记下来，附上足以判断「送到了没有」的错误码。**这条红线不靠「不会重跑」来守，靠「重跑时先重读那一行」来守**：任务队列的保证是至少一次，我们不跟它较劲；我们保证的是「至少一次」不等于「付两次钱」。所有时刻一律取数据库的时钟，不取应用进程的。
11. **进模型上下文的媒体必须配一条 tag，工具产出的地址必须够得着。** 往上下文里放一份媒体（用户附件、工具附回的图）时，同一位置必须放一条 `<kind url="…">`——种类只有它带得来，漏了那份媒体对素材校验就是隐形的，症状是模型看得见却用不了。反过来，工具产出的地址必须至少经**返回值**或**工作区文件**之一进入上下文：只落在外部系统里的地址，对模型等于不存在，它再想用也只能是编的。两条都漏了不会报错，只会静默失灵。

## 禁止逻辑

被刻意设计掉的推理模式，不得以「临时方案」名义重新引入：

- **信任客户端身份。** 任何来自 body / query / header（除凭证本身）的 userId、tenantId、role 都不得进入可信路径；run 按服务端事实定位，不按客户端提交的 id。
- **把 key 当角色用。** 不得给 key 授予「随属主角色自动膨胀」的权限；扩权只能重新显式授予。
- **伪造终态。** 运行事实不完整时只允许显式可重试错误，或以数据库已落库事实收尾；绝不为没有终态记录的 run 合成成功终态。事件流同理：生产者没留下结局就消失，收尾只能是「中断了，可重试」。
- **无声接不上。** 客户端带着位置来续读，而那个位置之前的事件已经不在了（过了重放窗口），必须明确拒绝并让它重新发起；绝不默默跳到当前位置，让客户端以为接上了、实则中间少了一段。
- **静默兜底。** 配置 env 缺失、持久化状态形状非法、协议边界损坏——都在最早的边界大声失败，而不是降级运行。
- **让模型自己认领素材。** 工具收到的地址一律按「这段对话里出现过吗」判，判据只取模型请求那一侧；模型正文里写下的、工具调用参数里给出的、以及厂商内建工具（联网搜索那类）带回来的地址，都不构成素材——否则模型写一句话就等于自己给自己发了通行证。校验失败的报错也不回显被拒的地址，回显一次它下一轮就成真的了。
