# ADR-0010: 对话素材台账——工具收的地址按表查，不按上下文文本查

- 状态：已接受（2026-09-04）
- 取代 `harness/materials.py` 原先的做法：把请求侧全部文本连成一段做子串匹配（PR #163 引入），并修订 **[ADR-0007](0007-tool-declaration-surface.md)** 决策 2 里 `materials_only(kind)` 的实现口径。
- **[ADR-0001](0001-architecture-foundations.md)**：Postgres 是唯一事实源，是本文的前提。

## 背景

工具收到一个地址，只有两个来源：从上下文里抄的，或者模型自己编的。原先的判法是把这次运行消息里请求侧的全部文本连成一段，问「这个地址逐字出现过没有」。它有三个结构问题：判定绑死了上下文完整性，历史一压缩地址就没了；子串包含让合法地址的前缀也算出现过；只认「出现过」不认「谁放进来的」，第三方经 API 发上来的任意地址与系统自己产出的地址同一待遇。

kimi 的做法是两条：用户附件按 `file_id` 引用、收件时拷进会话自己的 media 目录；工具产出的文件落在会话工作目录里，模型按路径引用，`ReadMediaFile` 判路径在不在工作目录之内。它的素材身份是「会话命名空间里的一个路径」，边界就是目录。我们的素材在对象存储里，没有目录边界，用一张表扮演这个角色。

## 决策

### 1. 一张表记「这段对话能用哪些素材」

`agent_runtime.materials`，四列：`namespace`、`url`、`kind`、`created_at`，主键 `(namespace, url)`。命名空间与工作区同一条规则（`namespace_for(owner, conversation_id)`）。协议 `MaterialLedger` 只有 `record` / `lookup` / `purge_namespace` 三口，放 `platform/material_ledger/`，PG 后端同目录；存储层不认识对话与用户。

### 2. 素材身份是 url 字符串

对方给什么 url 就存什么，不转存、不改写、不限域名、不解析 object key、不绑 assetId。收件只做形状检查：不是 http(s) 地址 → 422。`lookup` 逐字比对，不做前缀、不做归一化。

### 3. 只有两个门写台账

收下 prompt 时（`TranscriptService.submit`，重新生成与插话都经它）记附件；`shot_video` 每次往公开桶落地址时记（板、帧、整张网格图、设定图与其整图）。用户在正文里打的地址、模型自己写的地址都不算。

### 4. 校验仍是 `args_validator`，只换查的地方

范围规则照 ADR-0007 决策 2 挂在登记处，工具体不判来源。验证器是工具集上的 async 方法，查台账；共用的 `require_material(ledger, namespace, url, kind=...)` 在 `harness/materials.py`，查不到或种类不对抛 `ModelRetry`，错误消息不回显被拒地址。原先不问种类的 `require_recorded` 删掉：工具产出的地址过去没声明过种类，台账每行都带 `kind`。

### 5. 台账是来源约束，不是出网安全边界

它挡凭空捏造与跨对话串用。外部地址照旧由出网那一层（`OssMediaProbe`、拆片、ffmpeg 取板）自己管。

## 取舍

- **不回填历史对话。** 旧对话里的地址不在台账，工具会拒；正式测试从新对话开始。
- **不给 `media_assets` 加对话字段。** 那张表记「桶里有什么」，台账记「这段对话能用什么」，两个问题两张表。
- **不记来源、工具名、run。** 这个版本没人读；要审计看日志。
- **不做列表端点。** 面板要用再加。
- **接受同一份资产被多段对话用是多条台账行。** 桶里仍只一份，不像 kimi 那样按会话拷贝。
- **接受验证器逐个地址点查。** 参考图最多十来张，不需要批量接口。
