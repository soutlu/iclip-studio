# ADR-0031：「完成」是属主标记的任务层事实，`state=done` 改按它筛

- 状态：已接受（2026-09-18）
- 关联：[ADR-0008](0008-activity-from-agent-jobs.md)（活动状态由运行票据算出）、[ADR-0021](0021-conversation-soft-delete.md)（时间戳表达状态，可逆）、[ADR-0030](0030-list-order-by-created-at.md)（列表位置只随新建改变）
- 修订 [CONTEXT.md](../CONTEXT.md) 术语「对话」补一件事实；合同 [§6 对话](../../contract/conventions.md#6-对话-conversations) 的 `state` 取值与写路径、[§11 媒体生成](../../contract/conventions.md#11-媒体生成-generations) 补一条副作用；迁移 `0011_conversation_completed_at`。

## 背景

侧栏与审计的 `state=done` 标着「已完成」，实际含义是「跑过至少一轮且此刻没在跑」——一个从运行票据推出来的事实（ADR-0008）。属主要的不是这个：一轮跑完只说明机器闲下来了，分镜出来了他多半还要再改几版。他要的是「这活儿我收尾了」，是人的判断，几天才变一次，比运行层高一层。

两个含义共用「已完成」一个词，界面上必然打架。

## 决策

### 1. 用 `completed_at` 记属主的判断

`iclip.conversations` 加一列可空 `completed_at`：写入时刻表示已标记，抹回 `NULL` 表示取消，与 `deleted_at` 同一套写法（ADR-0021），天然可逆并留下标记时刻。不新建表——一段对话至多一个标记，一对一的单字段单独成表只多一次关联。

### 2. `state` 的 `done` 改按它筛，`running` 原样保留

`done` 从「跑过且空闲」改成「`completed_at` 非空」，新增 `open` 表示未标记；`running`（此刻有轮次在跑）语义不动。侧栏展示「全部 / 未完成 / 已完成」三个 chip，不再给 `running` 单独入口——此刻在跑由行上的指示点表达。保留 `running` 这个取值是因为筛选条件存在地址栏里（#371），删取值会让旧链接失效，而留着它不花任何代价。

### 3. 属主再动手就自动松开

开跑新一轮（`touch_run`）与提交任何一次出片，都把 `completed_at` 抹回空。出片这一路由组合根注入回调完成，与「挂上需求单即认领」同一种接法：生成域不认识对话表，受理成功后回头调对话域的用例，按属主限定、命中不到就静默跳过，失败只记日志不影响受理。

否则会出现「标了完成、回去重出一版视频、角标还挂着」的矛盾状态。

### 4. 机器永不自动标完成

反向不成立：轮次结束、出片完成都不写这一列。运行结束不等于人满意，自动标记会把「机器闲下来了」误当成「活儿干完了」。

### 5. 入口只在侧栏行菜单，标完不隐藏

标记与取消都在侧栏那一行的菜单里，对话页不加按钮。标完的对话照旧留在列表里、位置不动（ADR-0030），只在行尾多一个完成角标。

## 取舍

- **接受**：治理者失去「跑过且空闲」这个筛选视图。`running` 仍在，且审计列表本来就带人、单、时段、删没删四个筛选，这一个的价值最低。
- **接受**：`done` 这个取值的含义变了，旧链接不会报错但结果不同。取值不变、语义变，比删取值破坏更小。
- **不做**：异常报表不动。「空转」本来就只报没出过成片的对话，出过片的不会被误伤；标了完成却从没出过片的对话仍会被报空转，属主明确表示不管。
- **不做**：不联动需求单状态。一张需求单底下可以挂多段尝试，标完其中一段不等于整张单收工；需求单自身也没有「完成」这个状态。
- **不做**：不按完成与否隐藏或归档对话。那是另一套语义，等真有整理诉求再谈。
