# ADR-0013：做同款在建对话时只拷几份制作文件与素材台账，不带历史与血缘

- 状态：已接受（2026-10-07）
- 不取代已有 ADR；沿用 ADR-0012 的「只认明确选用」，把选用的图一律登记成对话素材。
- 影响：[CONTEXT.md](../CONTEXT.md) 的「对话」「对话素材」「工程文件」「制作页」「资料库」词条、[architecture.md](../architecture.md) 的对话分叉一段、[contract/conventions.md](../../contract/conventions.md) §6 的做同款与制作页换图、§13 的资料库详情；后端 [service.py](../../server/src/iclip/domains/conversations/service.py) 的建对话用例、[conversation_same_style.py](../../server/src/iclip/app/conversation_same_style.py)、[conversation_film.py](../../server/src/iclip/app/conversation_film.py) 的换图、[library/service.py](../../server/src/iclip/domains/library/service.py) 的详情。

## 背景

用户在资料库里看到一条做好的片，想换个人、换个商品或换个场景照着再做一条。AI 导演要的是那段对话的制作文件：方案、工程文件、运行文件、分镜；对话历史、出片记录、参考素材和拆解文档都用不上，带过来反而让 agent 照旧片的上下文接着聊。

比较过的方案：用分叉（带历史、记血缘、继承出片）；在第一条消息提交时再拷；建对话时就拷。拷什么：整个工作区；固定的几份文件。文件名：原样；工程文件与分镜文件改名。

## 决策

1. **建对话时拷。** `POST /conversations` 带 `sameAs`（源对话 id）就在建对话用例里拷，先拷文件与台账、最后落对话行，与分叉同一个顺序。发消息的路径不动；agent 开跑时工作区已经拷齐，不会看到拷了一半的文件。带同一个 id 重发时对话行已经在了，不再拷。
2. **只拷四份，两份改名。** 源里有的才拷：`treatment.md`、`film.icml` → `old_film.icml`、`film.icrun`、`video_shot.json` → `old_video_shot.json`；其余文件一概不拷。`film.icml` 与 `video_shot.json` 一出现，页面就自动打开制作页、分镜页；改名后要等 AI 导演改完、用 `move_file` 改回原名才打开。源里两份都没有就做不了，`422`。
3. **不带历史、不记血缘、不继承出片。** 这是它与分叉的区别：新对话就是一段新对话，`forkedFrom` 为空，资料库与审计都照普通对话算。
4. **源的可见范围同分叉。** 读得到才拷得动，治理者连墓碑也能拿来做；看不见是 `404`。
5. **源在跑也照拷。** 拷的是那一刻的文件，不等源收尾。
6. **选用的图一律登记成对话素材。** 制作页换图时，不论生成、编辑还是上传的图，写运行文件之前都登记进这段对话的台账；取消选用不登记。这样拷整份台账就带上了运行文件选用的每一张，新对话认得这些地址，不必另查源对话的生成记录。
7. **`canMakeSame` 只在资料库详情上。** 卡挂着对话、读者打得开、工作区里有 `film.icml` 或 `video_shot.json` 才是真；判断与拷贝共用一份文件表。

## 取舍

- **接受**：失败只留下寻址不到的文件与台账，没有统一回滚，同分叉。
- **接受**：拷的是源此刻的文件，源在跑时可能拷到 agent 正在改的那一版；要旧版本就等它跑完再做。
- **接受**：选用即登记让台账多出几条 agent 用得上的地址；这些图本来就是这段对话的。
- **接受**：列表的卡上不给 `canMakeSame`，前端在详情里才知道能不能做；列表上逐张读工作区太贵。
- **不做**：用分叉做同款。历史与血缘会把旧片的上下文带进新创作，出片继承也会让新对话的资料库卡混进旧片。
- **不做**：在第一条消息提交时再拷。那要动发消息的路径，失败语义也跟着变复杂。
- **不做**：拷整个工作区。参考素材、拆解文档与抽帧是旧片的，会误导 agent。
- **不做**：拷源对话的生成记录，或在新对话里按源对话的生成记录认图。台账已经带上选用的图，认图规则不用改。
