# ADR-0003：审计只数成功的生成，失败与在途不计

- 状态：已接受（2026-09-28）
- 取代 [ADR-0001](0001-video-domain-model.md) 第 10 条「审计出片次数：同组无来源的 video / generate 行，含失败与在途」。沿用该条「编辑段不计，副本不计」。
- 影响：[CONTEXT.md](../CONTEXT.md) 术语「审计口径」；合同 [§12 审计报表](../../contract/conventions.md#12-审计报表-audit)；[openapi.json](../../contract/openapi.json) 的 `/audit/*`（指标去掉出片镜数，任务执行的镜只给成功次数）。

## 背景

ADR-0001 §10 把一个镜名下全部出片记录都算作出片次数，失败的与还没出结果的也算。这量的是「试了几次」。

开发者判断这不是要看的东西。失败的生成不计费；治理者关心的是花费与结果是否达到业务要求。一次生成「成功」只说明这次请求成功了；业务上的通过，是这个镜只用一次成功生成就达标，成功次数越少花费越少。

按旧口径，上游连着失败三次再成功的镜会被记成出了 4 次、标成反复重试、不算一次通过，把不花钱的上游故障算到了人头上。素材有效率的分母也因此要另设「出片镜」（至少成功一次的镜），与每镜次数的分母「镜」不是同一批。

## 决策

1. **只数成功的生成。** 审计里的出片次数只算已完成的出片；失败的与还没出结果的不计。
2. **镜是至少成功生成过一次的（对话，镜号）。** 一次都没成功的镜在任何口径里都不出现。
3. **按成功次数定义镜上的指标**：每镜头重试次数 = 成功次数 ÷ 镜数；一次通过是只用一次成功生成就达标的镜，之前失败过几次不管；素材有效率 = 有人下载过的镜 ÷ 镜数；出片次数分布、出片次数最多的镜与反复重试异常都按成功次数。
4. **镜落在第一条成功生成的完成时刻**，不再是第一次出片的受理时刻。
5. **视频编辑仍不计。** 编辑段虽然调模型、计费，也不算回原镜头的次数；只有下载沿原作算回原镜。
6. **耗时与悬挂不跟着变**：单任务时长仍包含失败出片的生成时段，那是耗时、不是计费；视频悬挂仍看停在已提交上游、超过门槛的出片；只有失败或在途出片的对话仍算一次任务执行。

## 取舍

- **接受**：审计上看不到失败次数与失败率；上游故障多时，只能从视频悬挂与单任务时长间接看出来。
- **接受**：编辑段的花费不进每镜头重试次数，编辑多的镜看起来比实际省。
- **接受**：统计是现算的，改口径后历史数字整体按新口径重算，与改动前的截图对不上。
- **不做**：失败也算次数（ADR-0001 的做法）。会把不计费的上游失败算成返工。
- **不做**：一次通过要求第一次生成就成功。先失败后成功的镜，花费与一次就成的相同。
- **不做**：成功的编辑段算原镜头一次。编辑只重生成一段，按整条算会把成本说重；开发者选择维持现状。
