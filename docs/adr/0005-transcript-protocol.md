# ADR-0005: 对话协议换成 kimi code 的 transcript

- 状态：已接受（2026-08-31）；§4「一次 run 就是一轮」与取舍里「接受运行活在起它的那个进程里」「排队中的行不跨重启」被 **[ADR-0006](0006-durable-runs.md)** 取代（2026-09-01）
- 取代 **[ADR-0003](0003-detached-runs-and-replayable-streams.md)**：那一份用 AG-UI + Redis 事件流解决同一个问题。
- **[ADR-0001](0001-architecture-foundations.md)**：Postgres 是唯一事实源，是本文的前提。

## 背景

AG-UI 是一条**事件流**：客户端从头收到尾，自己在内存里拼出界面。这带来三件躲不开的事：

1. **历史归客户端拿着。** 每次发消息要把整段对话回传，服务端照它跑。客户端因此必须存一份消息历史，而那本该是服务端的事实。
2. **重连只能按位置重放。** 流是线性的，接不上就得从头再放一遍；为此要在 Redis 里留一条带重放窗口的流，多养一个有状态服务。
3. **界面形状没有协议。** 一次工具调用怎么显示、审批卡长什么样，全靠客户端按工具名各写一套；后端加一件工具，前端得跟着改。

kimi code 的 transcript 协议把这三件都收在协议里：结构化的轮/步/块、增量操作、服务端说了算的卡片形状。

## 决策

### 1. transcript 是投影，不是第二个事实源

持久事实只有官方 `StepPersistence` 存的那份消息历史。已经跑完的轮子从消息现推，正在跑的那一轮在进程内存里。所以没有「transcript 表」，也就没有它和消息历史漂开的可能——上下文压缩会改写消息，物化过的 transcript 会当场对不上。

代价是两条路必须给出逐字相同的结构，这由一组对齐测试钉住。

### 2. 编号从确定的事实算出来，不按到达次序

轮 = 一次 run（按消息上的 `run_id` 分组），步 = 这次 run 里第几次模型响应，块 = 这一步里正文与思考的次序。按「谁先到就给谁下一个号」编的话，一次模型重试就会让两条路永久分叉，而且不报错。

为此顶层 agent 的 `StepPersistence` 不设 `agent_name`：设了官方就自己铸 `{名字}-{短 uuid}`，与消息上的 `run_id` 是两套 id，轮的终态就查不出来。

### 3. 传输换成 WebSocket，Redis 退役

协议本来就是双向的（订阅、补批、停止、插话、审批都要往回说）。批次号加一个进程内的补批日志就够断线续传，不需要一条带重放窗口的外部流——**批次号重来是安全的**：客户端收到 `transcript.reset` 会把本地水位无条件覆写成帧里的 `seq`。这条是整个设计的支点。

Redis 至此没有别的消费者，整个退役。

### 4. 一次 run 就是一轮

审批用官方 `HandleDeferredToolCalls`：handler 可以是 async，在**同一次 run 内**等人点头。所以一轮不会被劈成两次 run，也就不需要「认领上一次留下的半截状态」那套。

停止走官方的 `CancellationToken`，不是 `task.cancel()`——外部取消是 `BaseException`，进不了官方收尾用的 `except Exception`，那一轮的终态操作一条都发不出去。

## 取舍

- **接受「协议字段名不按仓内 camelCase」。** transcript 面逐字照抄协议（信封 snake_case、实体 camelCase），因为客户端的 reducer 是照抄来的 zod schema。一半照抄一半翻译，写客户端的人得记两套。
- **接受「运行活在起它的那个进程里」。** 同 ADR-0003：进程没了运行就断。启动时收拾上一条命留下的 prompt 行，用户看到的是「失败了」而不是永远转圈。
- **接受一张 prompt 表。** 「一段对话同时只跑一条」这条挡板必须跨 worker——每个 worker 一份进程内存，谁也看不见谁在跑，没有库上的约束就会两个 worker 各起一次 run 往同一段消息历史里写。幂等键同理：重发可能打到另一个 worker。表的 `content` 列只服务同一条命里的接续，排队中的行不跨重启（启动时一并撤销）。

  订正（2026-08-31）：本条原先写的理由是「排队中的消息丢了就是用户打的字凭空消失，所以落库」。那没有兑现——启动收拾把排队的行撤销掉，而撤销掉的行队列视图查不到，用户重启后看到的是什么都没有。真理由是上面那条挡板。
