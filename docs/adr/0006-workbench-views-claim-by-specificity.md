# ADR-0006：工作台只登记专门视图，文件按越具体越优先认领

- 状态：已接受（2026-10-02）
- 修订（2026-10-07，ADR-0008）：常驻项登记了灰着的原因才在没有产物时列灰行。
- 不取代已有 ADR。
- 影响：[web/AGENTS.md](../../web/AGENTS.md) 的工作台登记说明；前端工作台注册表 [artifact.ts](../../web/src/shared/workbench/artifact.ts)、[registry.ts](../../web/src/shared/workbench/registry.ts)，选择页 [workbench-host.tsx](../../web/src/shared/workbench/workbench-host.tsx)。

## 背景

右侧工作台按注册表挑面板：分镜按确切路径 `video_shot.json` 认领并自动打开，「文件」面板认整个工作区，「委派任务」按工具卡头的类型认领。同一份文件被多项认领时取先登记的那项。点对话里的文件名也走注册表：被认领的文件进自己的面板，其余进「文件」面板的阅读页。「文件」面板用 `fileKindOf` 按后缀选 Markdown / JSON / 纯文本，没有后缀的看内容开头；审批卡预览也用它。

接下来要加的视图很可能认一类文件而不是一个固定路径，于是要回答：通用阅读器算不算注册项，一类文件怎么写，几项都认得同一份文件时归谁，谁决定自动打开，面板怎么写回，第一方面板要不要放 iframe。

业界的 agent 工作台大致三类：工具在元数据里指向一个界面、每次调用一个实例（MCP Apps、OpenAI Apps SDK）；组件绑定 agent 与前端共享的状态（AG-UI）；按文件挑视图、工作区文件是共用介质（VS Code、Cursor、Kimi Code、WorkBuddy）。本项目以第三类为主，「委派任务」按工具卡认领带一点第一类。

## 决策

1. **工作台分两层。** 注册表只回答「有没有专门视图认领这份数据」；没人认领的工作区文件由「文件」面板按原文显示（`fileKindOf`）。阅读器不做成注册项：没有后缀的文件要看内容才能判断，文件名模式表达不了；`fileKindOf` 与审批卡预览共用；阅读器显示在「文件」面板里面，不是独立标签。这与 VS Code 一致：自带的文本编辑器不是自定义编辑器中的一员，而是没人认领时的默认显示。
2. **认领方式有三种加一个整体项**：确切路径、文件名模式、工具卡头的类型，以及「整个工作区」。模式里 `*` 匹配一段路径内的任意字符、不跨 `/`，`**` 跨目录，`**/` 也可以一层目录都没有（`canvas/**/*.json` 也认 `canvas/a.json`），其余字符按字面认。语法自己实现，不引入匹配库。路径项、模式项与整体项是常驻项：还没有产物时选择页照样列一行灰的；按工具卡认领的项跟着那张卡来去。
3. **越具体越优先。** 同一份文件被多项认领时，确切路径 > 文件名模式 > 整个工作区；同一种认法之间按登记先后，两个模式都认得同一份文件时不比较哪个模式更具体。这样对错不取决于登记文件里的书写顺序，以后加的 `*.json` 视图抢不走 `video_shot.json`。
4. **自动打开由宿主按注册项决定**，不依赖模型调用展示类工具。WorkBuddy 的经验是模型经常忘记调这类工具。
5. **可编辑面板的写入与 agent 工具共用同一套后端操作**，校验与合并只写一次。文件类面板现已如此：面板写回工作区文件时，对话服务按路径套用文档校验，分镜用的是交付工具的同一个解析器。
6. **第一方面板直接嵌入页面，不放 iframe。** 概念命名对齐 MCP Apps（`ui://` 资源、`ui/update-model-context`、`displayMode`、`tools/call`、`hostContext`），第三方面板将来按 MCP Apps 接入。iframe 的收益（隔离、独立部署）只对别人的代码有意义；放进 iframe 后统一灯箱只能铺满 iframe，登录态要宿主转交，画布上的图拖进输入框要跨边界。MCP Apps 的界面跟着一次工具调用走，本项目的面板跟着一份长期存在、多方编辑的数据走，两者模型不同。

## 取舍

- **接受**：同一种认法之间仍按登记先后；两个模式重叠时由登记顺序裁决，不做模式之间的具体程度比较。
- **接受**：同一常驻类型可以有多件产物，选择页与标签栏一件一行。
- **不做**：「默认 / 备选」优先级字段。阅读器不进注册表后没有使用者；「换一种方式打开」（如分镜与 JSON 原文之间切换）等出现第二种看法时再议，想看原文仍可到「文件」面板。
- **不做**：先登记者生效。对错取决于书写顺序，把 `*.json` 视图写在分镜前面，分镜就悄悄打不开了。
- **不做**：把阅读器做成兜底注册项，理由见决策 1。
- **不做**：地址统一成 `file:路径` 并给旧链接加跳转。专门视图用 `?artifact=file:路径`，「文件」面板里的某份文件用 `?artifact=workspace&file=路径`，两种写法各有含义，统一没有现实需要。
- **不做**：本期让面板上报焦点、声明显示形态。第一个需要的面板出现时再定协议形态，命名对齐 MCP Apps 的 `ui/update-model-context` 与 `displayMode`。
- **不做**：第一方面板用 iframe，理由见决策 6。
