# ADR-0017: 需求单与对话的 id 可由调用方铸，期限不再是下发前提

- 状态：已接受（2026-09-07；2026-09-12 修订：决策 2 的 id 保留改由对话行自身的 `deleted_at` 承担，`conversation_ids` 表下线，见 [ADR-0021](0021-conversation-soft-delete.md)）
- 收窄 **[CONTEXT.md](../CONTEXT.md)** 不变量 8：客户端铸的 id 从「只做幂等键」扩到需求单与对话，归属与权限仍不由它决定。
- 合同 [§6 对话](../../contract/conventions.md#6-对话-conversations)与 [§8 需求单](../../contract/conventions.md#8-创作需求单-tasks)：`POST` 接受 `id`，幂等命中答 `200`；需求单另接受创建时的 `status`。

## 背景

外部服务（partner_app）代人发起创作：它先受理调用方的一次运行请求，再在这里建需求单、开对话、发消息、轮询、取回分镜表。它自己有一套业务编号，而且这套编号在它的异步任务、Redis 快照键和上游对话之间是同一个值。

服务端发放 id 时，这条链上每一步都要先拿到答复才知道自己创建了什么。中断重来就必须先「查有没有」：按标题搜需求单、按 `taskId` 列对话，猜哪一条是上次那条。猜错就是重复的需求单和重复的运行——而运行会真的花钱调模型。

需求单还有一道门：表上的 `tasks_deadline_check` 要求非草稿必须有期限，`publish` 也先看期限。机器提交的需求没有期限这个概念，人可以事后在前端补，但机器没法在创建时凭空填一个。

## 决策

### 1. `POST /tasks` 与 `POST /conversations` 接受调用方铸的 `id`

- 两个端点的请求体都加可选 `id`（UUID）；不给仍由服务端 `uuid4()` 生成。
- 需求单写入走 `ON CONFLICT (id) DO NOTHING` 再回读；对话先在同一事务认领永久保留的 ID，再写入对话行。命中已有记录时不写入，答复那一条并把状态码降为 `200`，新建仍 `201`。调用方据此区分「我建的」和「已经在了」。
- 幂等只按 id 判定，**不比对内容**：重发时字段有差异一律以已有记录为准，不做合并、不报冲突。需求变了就换一个 id。

### 2. id 不是身份凭证

- 对话有属主：命中的那一段属于别人时抛 `NotFound`，与按 id 读别人的对话同一个口径，不泄露它存不存在，更不把它交给撞上 id 的人。
- 对话删除后，运行历史仍按原对话 ID 保留，所以 ID 不得重新分配给任何人。`iclip.conversation_ids` 只存已经成功使用的 UUID，不随对话或用户删除；重用已删除对话的 ID 返回 `404`。创建失败时事务回滚，不占用 ID。2026-09-12 修订：保留表下线，对话行改为标记 `deleted_at` 留在原表占住 id，语义不变，见 [ADR-0021](0021-conversation-soft-delete.md)。
- 需求单没有属主（持 `tasks:read` 可见全部），所以幂等命中直接答复已有那一张；创建者仍取自登录身份，请求体带 `creatorUserId` 照旧 `422`。
- 主键冲突从「归属引用不存在」里分了出来：对话仓储原先把所有 `IntegrityError` 都当成外键缺失，现在主键交给幂等分支，剩下的才是需求单或合集不存在。

### 3. 需求单创建时可以直接落 `published`

- `POST /tasks` 接受 `status`，只允许 `draft`（缺省）与 `published`；之后的流转仍只走状态机端点，`PUT` 带 `status` 是 `422`。
- 机器提交的需求本来就是定稿，落成草稿再补一次 `publish` 只是多一次往返，而 `publish` 是「创建者本人或治理者」的操作，机器身份去发布人写的草稿并不合适。

### 4. 期限彻底可选

- 删掉表上的 `tasks_deadline_check`，以及服务层「发布前必须定下期限」和「已下发的需求单必须有期限」两条校验。
- `publish` 保留的仍是「填了期限就不能已经过期」：有期限的单子不能带着过期的期限下发，没填的不拦。
- 取舍：期限从「下发的前提」退回「需求方的一句要求」。人工流程里它照旧可填可改，但不再有任何地方强制它存在——机器提交的需求单不需要为了通过校验编一个日期。

## 影响

- 调用方可以在服务端答复之前就把自己的记录串好，中断后原样重放安全，不需要按标题搜索来恢复。
- `TaskRepository.create` / `ConversationRepository.create` 换成 `create_if_absent`，返回 `(记录, 是否新建)`；服务层与内存替身同步。
- 已经存在的无期限非草稿需求单会让 0025 的降级失败，降级前须先补期限或退回草稿。
