# ADR-0006：资料库标签是数据，两库共用一棵树，打标是独立的一条流程

- 状态：已接受（2026-10-21）
- 修订（2026-10-21，[ADR-0007](0007-library-tag-value-depth.md)）：第 1 条的取值层级上限改为三级。
- 影响：[CONTEXT.md](../CONTEXT.md)「参考视频」「标签」词条；[contract/openapi.json](../../contract/openapi.json)；[跨端合同](../../contract/conventions.md) §14、§15；[architecture.md](../architecture.md)。

## 背景

参考视频原来有两组写死在代码里的标签（八种片子类型、一份品类清单），拆解完在同一次任务里打标。资料库还要收爆款素材，同样按标签找；维度与取值需要运营随时调整，不该每次改代码、加迁移。

## 决策

1. 标签是数据：一张表存一棵树，顶层是维度，维度下是取值，取值下最多再一层；维度与取值由治理者配置。
2. 灵感库与爆款素材库共用这一棵树。每一库的一条在标签里是一个条目（种类加指向那一库的外键），标签记在条目上。
3. 维度上的 `auto_fill` 决定谁打：`ai` 由 AI 打，空的只靠人填。打标只整组重写 AI 维度，人工维度从不被打标动；人和 AI 改同一维度，后写的为准，不记来源、不加锁。
4. 打标独立于拆解，是自己的一条后台流程和队列：按条目种类取文字，按当时树里的 AI 维度现拼提示词与输出约束，选了小类就去掉大类。失败记原因，只清 AI 维度；不自动重试。
5. 筛选按维度分组：同一维度命中任一，维度之间都要命中，上级含下级。

## 取舍

- 接受：
  - 树改了以后，已打的标签不会自动跟着重打，要人重新打标；
  - 删一个标签会连带删掉它的下级和所有条目上的这个标签；
  - 种类、`auto_fill` 与状态的取值只由代码保证，表上不加 CHECK。
- 不做：
  - 每个库各建一张标签关联表；
  - 一张关联表用多态外键指向不同的库；
  - 把维度与取值继续写死在代码里。
