# ADR-0006：资料库标签配置化存储，两库共用标签树并独立执行 AI 打标

- **状态**：已接受（2026-10-21）
- **后续修订**：2026-10-21 由 [ADR-0007](0007-library-tag-value-depth.md) 将第 1 条的维度下标签层级上限由两级扩展为三级
- **影响范围**：[CONTEXT.md](../CONTEXT.md)（参考视频、爆款素材、标签）；[contract/openapi.json](../../contract/openapi.json)；[contract/conventions.md](../../contract/conventions.md) §14–§16；[architecture.md](../architecture.md)

## 背景

最初参考视频的分类标签（8 种视频类型与固定品类清单）是硬编码在代码里的，且与视频拆解绑在同一个后台任务里执行。随着资料库新增「爆款素材库」，两个库都需要按统一的标签体系筛选，并且运营人员需要随时增删改分类维度、调整 AI 打标判据，不能每次改标签都改代码和发版。

## 决策

1. **标签树作为动态数据存表**：使用单表（通过 `parent_id` 自关联）存储整棵标签树，顶层为「维度」，维度下为多级标签取值（层级上限见 [ADR-0007](0007-library-tag-value-depth.md)），由管理员在界面上动态维护。
2. **灵感库与爆款素材库共用同一棵标签树**：每个参考视频或爆款素材在标签模块中对应一条「打标条目（Entry，通过类型加对应库外键唯一约束）」，标签绑定在条目上。
3. **区分 AI 维度与人工维度**：维度上的 `auto_fill` 字段决定该维度由谁打标（设为 `ai` 由大模型自动打标，设为 `null` 则仅由人工勾选）。AI 自动打标只会整组覆盖 `auto_fill: "ai"` 的维度，绝不触碰人工维度的标签；人工也可以随时修改 AI 维度的标签（后写入者直接覆盖，不加锁、不区分标签来源）。
4. **打标拆分为独立的后台异步队列**：打标与视频拆解解耦，拥有独立的任务队列（`tagging`）。执行打标时，根据条目类型读取文本（参考视频读拆解报告，爆款素材读所属对话的 `treatment.md`），并按当时标签树中最新的 AI 维度动态生成 JSON Schema 约束调用大模型；如果模型同时选中了子标签和父标签，落库时自动去掉冗余的父标签。打标失败时清空 AI 维度标签并记录失败原因，不自动重试。
5. **统一的标签筛选逻辑**：按标签筛选列表时，**同一维度内多选为「或（OR）」关系（且选中父标签自动包含其下所有子标签），不同维度之间为「且（AND）」关系**。

## 取舍

- **接受**：
  - 管理员修改标签树（改名、改说明、开关 AI 打标）后，存量条目不会自动触发全量重打标，需按需点击重新打标；
  - 删除某个标签节点会通过外键级联删除其所有子标签，并从所有已打标条目上移除这些标签。
- **不做**：
  - 不为每个资料库分别建一套独立的标签表；
  - 不再在代码里硬编码任何标签名称与分类枚举。
