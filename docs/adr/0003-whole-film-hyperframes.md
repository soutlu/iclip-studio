# ADR-0003：整片基于 HyperFrames 重写，草稿存服务端，导出时渲染

- 状态：已接受（2026-10-17）
- 影响：[CONTEXT.md](../CONTEXT.md)「生成任务」「生成结果」「资料库」「审计口径」「埋点事件」词条；[contract/openapi.json](../../contract/openapi.json)；[跨端合同](../../contract/conventions.md)；[architecture.md](../architecture.md)；[deploy.md](../deploy.md)。

## 背景

原来的整片在浏览器里预览、用 ffmpeg 导出，字幕排版和混音两边各写一套，靠金样对账仍有差异。现有的编辑器和渲染已经下线。HyperFrames（Apache-2.0）用同一份 HTML 合成页面在浏览器里预览、在无头 Chrome 里逐帧导出，并且自带成熟的剪辑交互、组件库和拍点分析。千问识别对中文给出逐词时间。

## 决策

1. 整片的预览和导出用同一份 HyperFrames 合成页面，由同一份 TypeScript 代码从草稿生成：编辑器在浏览器里生成后交给它的播放器预览；导出由独立的渲染服务（Node、`@hyperframes/producer`、Chrome、GPU）生成并渲染。合成格式、剪辑行为和组件都以 HyperFrames 为准。不自写排版、混音、响度和限幅规则，声音只应用用户设的音量。
2. HyperFrames 的引擎包作为依赖安装。Studio 只复制需要的纯逻辑源码：时间线的拖动与修剪、吸附、缩放，以及画面拖动的吸附与参考线；不安装 Studio 包。组件库按固定版本复制进项目，构建时下载并校验，组件引用的外部脚本和字体一起存到本地；在我们的画面上不能正常工作的组件不收。整片页面的界面和业务由我们自己实现。
3. 每段对话一份整片草稿，自动保存在服务端，没有版本。时间线采用 HyperFrames 的片段模型（轨道、开始时间、时长、素材入点），每个视频片段记录它出自哪条成片。拖动、修剪、拆分、吸附的手感照 Studio；画面轨始终首尾相接是我们的规则，每次编辑后整轨收紧，字幕和转场跟着各自的段走，音乐和包装不跟随。
4. 不保存成片。每次「导出」都按当前版本重新渲染：产物放在对象存储的临时位置，给出短期有效的下载地址，到期自动删除，不建生成记录。导出进度只记在渲染服务里，渲染服务重启后进行中的导出作废，需要重新导出。整片不再是生成记录，资料库不再设整片页，已有的整片记录全部删除。
5. 下载导出的整片时，它用到的每条成片各记一次下载，按现有规则计镜。
6. 页面分上下两块时间线：上方是成片区，有画面、字幕、音乐、包装几条轨；下方是视频素材区，按原作分轨。左侧栏分「素材」（音乐）和「组件」（组件库）两个标签。不设右侧属性栏，编辑都在轨道上完成。入口是分镜页、制作页顶栏的「整片」按钮。
7. 字幕使用逐词时间。识别仍用 `qwen-audio-3.1-asr-flash`，保存每句的逐词时间。用户改过字的句子和没有逐词时间的旧记录，在这句原来的起止时间内按字数平均分配。字幕样式来自组件库。
8. 音乐取这段对话生成或上传的音频记录（上传的音频可以挂到对话上），铺满整片（包括片头片尾），起点和音量由用户定。拍点由前端用 `@hyperframes/core/beats` 分析。「自动卡点」不动音乐，把切点挪到最近的拍点，后面的片段跟着移动；会切断口播、或素材不够长的切点保持不动。
9. 片头片尾是组件：拖到成片的开头或结尾，默认 2 秒，时长可以拖动调整。组件的可填项都可以改，其中品牌名和标语默认取资料库的品牌模板；在整片里修改只影响这一条整片。品牌模板里的片头片尾视频不再使用。

## 取舍

- 接受：
  - 每次导出都要等渲染完成；
  - 引擎或组件升级后，同一份草稿重新导出的结果可能和以前不同；
  - 片段之间的响度不统一，切点处没有淡入淡出；
  - 字幕的折行和样式由组件决定；
  - 导出依赖带 GPU 的渲染服务；
  - 改过字的句子，逐词时间是估算的；
  - 只适配英文的字幕组件、自带演示画面的转场组件不收进组件栏。
- 不做：
  - 保存成片或草稿版本；
  - 在用户的浏览器里导出；
  - 安装 Studio 包，或复制它的界面组件；
  - 复制 hypit 的代码；
  - 右侧属性栏。
