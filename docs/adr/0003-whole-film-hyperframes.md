# ADR-0003：整片基于 HyperFrames 重写，草稿存服务端，导出时渲染

- 状态：已接受（2026-10-17）
- 影响：[CONTEXT.md](../CONTEXT.md)「生成任务」「生成结果」「资料库」「审计口径」「埋点事件」词条；[contract/openapi.json](../../contract/openapi.json)；[跨端合同](../../contract/conventions.md)；[architecture.md](../architecture.md)；[deploy.md](../deploy.md)。

## 背景

原来的整片在浏览器里预览、用 ffmpeg 导出，字幕排版和混音两边各写一套，靠金样对账仍有差异。现有的编辑器和渲染已经下线。HyperFrames（Apache-2.0）用同一份 HTML 合成页面在浏览器里预览、在无头 Chrome 里逐帧导出，并且自带成熟的剪辑交互、组件库和拍点分析。千问识别对中文给出逐词时间。

## 决策

1. 整片的预览和导出用同一份 HyperFrames 合成页面，由同一份 TypeScript 代码从草稿生成：编辑器在浏览器里生成后交给它的播放器预览；导出由独立的渲染服务（Node、`@hyperframes/producer`、Chrome、GPU）生成并渲染。合成格式、剪辑行为和组件都以 HyperFrames 为准。不自写排版、混音、响度和限幅规则，声音只应用用户设的音量。
2. HyperFrames 的引擎包作为依赖安装，其中 SDK（`@hyperframes/sdk`）用于在预览画面上判断点中了哪一块、哪里画了东西。Studio 只复制需要的纯逻辑源码：时间线的拖动与修剪、吸附、缩放，以及画面拖动的吸附与参考线；不安装 Studio 包。组件目录（`catalog.json`）由人工维护，收哪些组件以它为准；组件库按固定版本在构建时下载并校验，只装目录收录的组件，组件引用的外部脚本和字体一起存到本地；在我们的画面上不能正常工作的组件不收。整片页面的界面和业务由我们自己实现。
3. 每段对话一份整片草稿，自动保存在服务端，没有版本。时间线采用 HyperFrames 的片段模型（轨道、开始时间、时长、素材入点），每个视频片段记录它出自哪条成片。拖动、修剪、拆分、吸附的手感照 Studio；成片轨始终首尾相接是我们的规则，每次编辑后整轨收紧，字幕跟着各自的段走，音乐和特效不跟随。
4. 每次「导出」都按当前版本重新渲染，是一条生成记录（种类 `whole_film`、操作 `render`），由生成队列推进，渲染服务是它的执行方。渲染好的整片上传成公开对象、永久保留，每次导出都留着；导出的整片出现在资料库的「成片」页。渲染服务重启后，进行中的导出记为失败，用户重新导出；取消的导出记为失败，错误码 `CANCELLED`。旧版整片的记录全部删除。
5. 下载导出的整片时，它用到的每条成片各记一次下载，按现有规则计镜。
6. 页面分上下两块时间线：上方是成片区，有成片、特效、字幕、音乐四条轨；下方是视频素材区，按原作分轨。左侧栏分「素材」（音乐）、「品牌」、「通用」三个标签：有品牌的组件放在「品牌」下，按品牌分组；其余组件放在「通用」下，按分类排列。这只是页面上的分栏，放置和导出都不看它。不设右侧属性栏。在预览画面上点视频、组件或字幕，等于在时间线上选中它；双击字幕或组件里带标记的字，直接在画面上改。组件的设置仍从轨道上的块打开。入口是分镜页、制作页顶栏的「整片」按钮。
7. 字幕使用逐词时间。识别仍用 `qwen-audio-3.1-asr-flash`，保存每句的逐词时间。用户改过字的句子和没有逐词时间的旧记录，在这句原来的起止时间内按字数平均分配。字幕样式来自组件库。
8. 音乐取这段对话生成或上传的音频记录（上传的音频可以挂到对话上），铺满整片（包括片头片尾），起点和音量由用户定。拍点由前端用 `@hyperframes/core/beats` 分析。「自动卡点」不动音乐，把切点挪到最近的拍点，后面的片段跟着移动；会切断口播、或素材不够长的切点保持不动。
9. 组件和视频一样是片段，它和视频的关系只看放在哪条轨上。放在成片轨上，它是与视频段同等的一段，占用时间，后面的段跟着让开；放在特效轨上，它叠在画面上，有自己的起止时间。转场就是放在特效轨上的普通特效，没有单独的规则。片头片尾不单独区分，只是恰好排在最前或最后的组件段。组件目录里的放置位置只决定点击卡片时默认放到哪里，不限制组件能放在哪里。品牌的片头片尾是为每个品牌事先做好的组件，编辑器不从品牌设置里自动填任何内容。组件的可填项都可以改，在整片里修改只影响这一条整片。特效块和整片字幕可以在画面上拖动换位置，位置记为 HyperFrames 的 `data-x`/`data-y`；成片轨上的段不能拖。

## 取舍

- 接受：
  - 每次导出都要等渲染完成；
  - 引擎或组件升级后，同一份草稿重新导出的结果可能和以前不同；
  - 片段之间的响度不统一，切点处没有淡入淡出；
  - 字幕的折行和样式由组件决定；
  - 导出依赖带 GPU 的渲染服务；
  - 改过字的句子，逐词时间是估算的；
  - 只适配英文的字幕组件、自带演示画面的转场组件不收进组件目录。
- 不做：
  - 保存草稿版本；
  - 把淡入淡出做成组件，以后要做时作为成片段的属性；
  - 在用户的浏览器里导出；
  - 安装 Studio 包，或复制它的界面组件；
  - 复制 hypit 的代码；
  - 右侧属性栏。
