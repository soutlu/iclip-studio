# ADR-0014: 子代理面板走产物宿主，前端按 agent 订阅，气泡按 id 认领

- 状态：已接受（2026-09-05）
- 补充 **[ADR-0009](0009-storyboard-workbench.md)** 决策 1：产物注册表登进第二条，工具帧来源正式启用；补充 **[ADR-0012](0012-subagent-transcript.md)**：子代理流在前端怎么看；执行 **[ADR-0013](0013-transcript-protocol-freeze.md)** 决策 4 的认领口径。

## 背景

后端每个子代理一条 transcript 流，按 `agent_id` 读；主流工具卡上的 `agentRefs` 指向它。前端此前只订主流：连接层一段对话只留一份订阅回调，工作台宿主因此一直没接工具帧产物。kimi 网页端把子代理放在右侧栏里，同时只开一个，点卡打开。

## 决策

### 1. 连接层按 (对话, agent) 分订阅，读取器按流共用

`subscribe_v2` 整张表一帧上行，各 agent 各带档位与水位；帧按 `agent_id` 分发；`unsubscribe_v2` 可只退一个 agent。服务端回 `code: 404` 时只退这帧新加的子代理，原本订着的不动，主流重订；重连重发整张表时分不清是谁，就退掉全部子代理。

读取器按 (对话, agent) 登记、引用计数：第一个持有者到来时订阅，最后一个走了才停，停下即清空内容。聊天页与右侧面板同时看同一条流拿到同一个实例。

### 2. 子代理面板是一件产物，点派活卡打开

- 注册表新增匹配方式 `displayKind`：工具帧按服务端 `display.kind` 命中，派活卡是 `agent_call`。帧来源带上 `display` 与 `agentRefs`，面板按第一个 `agentId` 读那条流。
- 主流里的每张工具卡都是候选，命不命中由注册表定；宿主的帧来源就是共用的主流读取器。
- 子代理面板不自动打开；点卡上的「查看」把 URL 的 `artifact` 参数设成这张卡，并向宿主发一次打开请求，用户之前的折叠随之作废。
- 与分镜在同一个宿主里，切换器切，同时只显示一个。

### 3. 面板内容

顶部是子代理名、状态标签、耗时；正文复用轮渲染：开场气泡就是派下去的任务，下面是它的思考、工具与回复。读取失败显示「无法加载这个子代理的对话」加重试。

### 4. 乐观气泡按 id 认领

轮头 `triggerPromptId` 认发出去的那句，插话块 `promptIds` 认插队的那句；只有服务端没给 id 的轮才退回比内容。锚点逻辑删除。

## 取舍

- **不给子代理面板单独一条右侧栏。** 宿主已经管几何、折叠、切换与中断点，再造一套就是两份。
- **点卡开面板靠 URL 参数加一次打开请求，不靠宿主监听 URL。** 只靠参数时，用户折叠后再点同一张卡地址不变、面板不动。
- **主流之外的帧来源暂不做「已完成才算产物」。** 派活卡跑着的时候就要能点开；等有按 `view` 命中的渲染器再定它的口径。
- **接受 mock 的子代理流用整块替换而不是逐字追加。** 页与推送对得上就行，演示环境不追求与真后端同一种增量。
