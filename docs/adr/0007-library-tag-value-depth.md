# ADR-0007：维度下支持三级标签取值

- 状态：已接受（2026-10-21）
- 取代 [ADR-0006](0006-library-tags-as-data.md) 第 1 条的层级上限，其余决策沿用。
- 影响：[CONTEXT.md](../CONTEXT.md)「标签」词条；[跨端合同](../../contract/conventions.md) §15；[architecture.md](../architecture.md)。

## 背景

场景需要保留「城市通勤与生活 → 早晚高峰通勤 → 地铁/公交拥挤站立 (防滑/耐脏)」这样的三级取值。原来的两级上限会丢失层级；把上级并入名称又会让管理、筛选和 AI 判断各自解释路径。

## 决策

1. 维度之下最多三级取值，维度本身不计入三级。继续使用现有 `parent_id`，不增加表或列。
2. 管理、人工补标签、筛选和 AI 打标共同读取这棵树。AI 输出约束与结果解析逐层限定父子关系；选中下级时不再保存它的上级。
3. 场景名称与层级由治理者维护，不写入运行时代码；改树不自动重打已有条目。

## 取舍

- 接受：管理与选择组件需要展示第三层，AI 输出约束需要递归表达。
- 不做：把层级拼入名称、另建场景专用表或增加无限层级。
