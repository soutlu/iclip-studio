# ADR-0018：视频生成接口镜像上游异步接口

- 状态：已接受（2026-09-09）
- 关联：[ADR-0004](0004-generation-queue-in-postgres.md)（排队与判失败规则不变；§8 关于视频转存的部分由本文替代）、[ADR-0009](0009-storyboard-workbench.md)（生成任务归属到对话，本文再加需求单）、[ADR-0017](0017-client-minted-record-ids.md)（调用方铸 id 的语义，本文没有引入幂等键）

## 背景

视频生成的上游是公司内一个视频异步服务：提交拿任务号，再查状态。它同时也是调本系统 agent 接口的调用方，用它自己那套字段与调用代码。本系统原先的视频提交接口是自己设计的形状：camelCase、字段名不同、`kind` 判别式与图片共用一个地址、状态词自己的一套、结果转存成本系统的对象。外部调用方要接视频出片，就得在两套形状之间逐字段对映射。

## 决策

### 1. 对外照抄，对内不动

`POST /generations/video` 镜像上游请求，另有本地归属字段与结构化 `shot` 扩展；`shot` 由服务端拼成 `prompt`，自身不转发上游，具体约定见[跨端合同](../../contract/conventions.md#视频镜像上游异步接口)。响应只有 `task_id`。`GET /generations/video/{task_id}` 照上游任务查询的形状，状态词用上游的。队列、`submitting` 守卫、判失败规则、轮询节奏一律不变；改的只是接口的外壳与适配器的转发方式。

调用方拿现成的上游调用代码，改地址、换认证头、加归属字段就能用；这是唯一目标，所以字段名连命名风格都照抄，在跨端约定里记成 camelCase 的例外。图片端点不镜像图片网关：它的调用方是本系统自己的前端与 agent 工具，字段是本系统自己的。

### 2. 不复制上游的模型能力校验

本系统只拦自己能判的：模型在运行配置的允许表里、地址是 http(s)、秒数不小于 -1、未知字段，以及本地 `shot` 的结构与引用一致性。画幅、时长范围、分辨率、素材规格由上游按模型判。复制一份只会漂。代价是上游的 `400` / `422` 到调用方那里是记录里的 `failed`，不是当场报错：提交仍在后台（ADR-0004 §2），本文不改。

上游会丢弃的 `session_id` 与废弃别名 `image_urls` 在这里是 `422`：不做静默忽略，也不留兼容别名。

### 3. `user_name` 是归属标签，从提交方来

两种生成都带 `user_name`，上游按它落表对账。它不是身份：不参与授权，不决定行归属，行归属仍是 `owner_user_id` / `api_key_id`。取值规则与发消息相同（`resolve_user_name`）：API key 调用方必填、照收；浏览器会话由服务端填登录用户名。agent 出图取运行依赖里随消息进来的那个名字，不取运行主体——经 API key 触发的运行，主体是服务账号，名字才是真正提需求的人。配置里写死的调用方标识删掉。

### 4. 需求单 id 落列

`generation_jobs.task_id` 是调用方给的需求单 id，可空、不建外键、带索引，`GET /generations` 可按它筛。对话能反查到需求单，但生成记录要按需求单直接查，走列比走两次查询清楚。请求体里叫 `task_id` 沿用上游对需求单的叫法；它与响应里的 `task_id`（本系统的生成记录 id）是两个层级，合同里写明。

### 5. 视频不转存，直接存上游的两个地址

上游成功时给的是它自己发布到公司对象存储的原片与水印版地址，稳定不过期；再抄一份是重复存储。两个地址都要有，缺一份判失败，因为上游的合同是两份都发布完才进成功。图片仍然转存：图片网关给的是会过期的签名地址。

### 6. 提交阶段的错误码分清「送到了没有」

连不上是 `PROVIDER_UNREACHABLE`；连上了却没拿到结果（读超时之类）在提交阶段是 `PROVIDER_RESULT_UNKNOWN`，请求可能已被收下。两者在提交阶段都是终态（不变量 10），差别只是对账时能分清。查状态是幂等的，仍按不可达处理。

## 取舍

- **接受**：同一个 `/generations` 前缀下两种命名风格并存。图片端点若也改成 snake_case，本系统前端与工具要跟着改一遍，却没有外部调用方受益。
- **接受**：视频记录的两个地址是外部系统的地址，本系统不控制它们的生命周期与跨域策略。前端的下载与截帧假定地址在本系统的桶里，接回出片入口时要在真跑里核。
- **接受**：上游的参数错误要到查状态才看到。要当场报错得把视频提交挪进请求里同步做，那会改 ADR-0004 的排队方式，等实际用起来再看。
- **不做**：幂等键。外部调用方重发提交会产生第二条付费任务，与对话、需求单接口不一致；另开一轮，形状照 ADR-0017。
- **不做**：改鉴权体系。`user_name` 只是标签，加它不碰角色、权限词与 API key 归属。
