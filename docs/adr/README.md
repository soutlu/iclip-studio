# 架构决策记录（ADR）编写规范

本目录存放项目中已经拍板定案的架构决策。新增或修改 ADR 时请遵守以下规则（普通文档和代码注释中如何引用 ADR，见 [AGENTS.md](../../AGENTS.md#4-文档维护)）：

- **存放位置与命名**：统一放在 [docs/adr/](./) 目录下，前后端共用；文件名格式为 `NNNN-slug.md`，编号从 `0001` 依次递增。
- **什么内容才写 ADR**：只记录由开发者明确拍板、且同时满足以下三个条件的决策（尚在讨论阶段的草稿不入库）：
  1. 一旦实施后很难低成本推翻；
  2. 如果不交代当时的背景，后来看代码的人会觉得奇怪；
  3. 当时确实对比过其他备选方案。
- **正文结构**：
  - 标题格式为 `# ADR-NNNN：<决策一句话总结>`；
  - 开头列出「状态与日期」「取代或沿用了哪篇旧 ADR」「影响哪些文档」；
  - 正文固定分为 **「背景」「决策」「取舍（分『接受』与『不做』）」** 三节，只写最终决策与取舍理由，不写开发进度。
- **后续决策变更怎么办**：已经接受的 ADR 除修正错别字或失效链接外，**不再直接修改原决策内容**。如果后来推翻或调整了某项决策，请新建一篇 ADR 并在开头注明「取代 ADR-NNNN 第 N 条」，同时在旧 ADR 开头更新状态为「已被 ADR-NNNN 取代」或追加一行「修订（日期，ADR-NNNN）」。
