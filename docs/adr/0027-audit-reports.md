# ADR-0027：审计报表是跨模块的只读读模型，直接查表

- 状态：已接受（2026-09-15）
- 修订（2026-09-22，[ADR-0032](0032-generation-root-job.md)）：出片与 `missing_shot` 的判据加上「独立记录」（`root_job_id IS NULL`），衍生记录不再靠便签键排除。
- 关联：[ADR-0020](0020-generation-metadata.md)（镜头坐标在 `metadata.shot`）、[ADR-0024](0024-audit-deleted-conversations.md)（治理者能读墓碑）、[ADR-0026](0026-conversation-usage-ledger.md)（对话用量台账）
- 修订 [CONTEXT.md](../CONTEXT.md) 新增术语「审计口径」；[architecture.md](../architecture.md) 持久化表补一行；合同新增 [§12 审计报表](../../contract/conventions.md#12-审计报表-audit)。

## 背景

领导要看产量、成功率、耗时与模型消耗，从全体一路下钻到人、需求单、对话、镜。这些数字横跨 `iclip.generation_jobs`、`iclip.conversations`、`iclip.tasks`、`agent_runtime.agent_jobs`、`agent_runtime.conversation_usage` 五张表，归三个业务模块与 harness 所有。

项目里跨模块协作的惯例是组合根注入协议：对话模块拿 `busy_conversation_ids`、`activities_of` 这样的窄口子。给一个只做聚合的报表注入五个读协议，每个协议还得暴露足够细的行让报表在内存里 join 与分组，比报表本身重，也把聚合从数据库搬到进程里。

## 决策

### 1. 新模块 `domains/audit`，只读、按表名直接查

`reports_pg.py` 用 `text()` SQL 与绑定参数直接查上述五张表，一个连接跑完一次报表。它不建表、不迁移、不写入，也不定义这些表的元数据；tach 上只依赖 `common`、`platform.db`、`identity`。框架围栏把它当外部只读适配器登记，与 `products/catalog_pg.py` 同一类，不叫 `infra_sql.py`，因为那个名字表示模块自有表。

表结构归各自的模块演进；报表 SQL 引用的列一旦被改动，报表的集成测试会先红。这是有意接受的耦合：读模型跟着事实源走，而不是要求事实源为报表暴露接口。

### 2. 一份指标形状服务所有维度

`Metrics` 一个 dataclass：成片、镜、运行、周期、视频耗时、用量六组原始计数与分布。全体、人、需求单、时段、对话五个维度都是它，只是维度键不同；SQL 也只有一份，差别在五段 CTE 各自的分组键表达式（各指标的时间锚点不同，键要在自己的 CTE 里算）。运行单独一段，让只跑过没出片的人也在按人里占一行。比率（每镜平均次数、一次通过率、缓存命中率、每件成片 token）在 dataclass 上派生，分母为零给 `None`，不进 SQL。

### 3. 出片次数分布只给全体，曲线与集中度在前端算

`summary` 多一段 `attemptDistribution`：每镜的出片次数分档计数，不封顶，锚点与每镜次数一样看该镜首次出片时刻。它不进 `Metrics`——那是五个维度共用的形状，按人、按需求单、按时段的每一行都背一个数组不值当；筛选条上的人与需求单同样作用在它上，要按人看分布就是筛一次的事。

口径上**停下就算有结果**：次数是这个镜名下的全部出片记录数，不看终态，出过视频就算这一镜收工了。所以累计通过曲线末档必然收在 100%，没有「没成」这一档，也不存在删失——前期设计里的置信带与在险镜数因此没有信息量，没有做；样本可信度改在悬停里给「进到这一次还有多少镜」。累计曲线、洛伦兹曲线与集中度（基尼系数）都由前端从这份原始分布算，与「比率在 dataclass 上派生、不进 SQL」是同一条原则；集中度必须吃未折叠的分布，展示层折的「5 次以上」只影响画图。

### 4. 端点按前端一次渲染的单元切，不按指标切

三个端点：`summary`（全体 + 每人 + 每单 + 可选时段序列，一屏看完、同一组筛选）、`conversations`（要翻页的明细，每行内嵌镜与按模型用量）、`anomalies`（要按种类筛、阈值可调、要翻页的列表）。都要 `users:manage`，与 `GET /conversations/audit` 同一权限、同一游标翻页方式——游标的编解码与列表上限由 [platform/paging.py](../../server/src/iclip/platform/paging.py) 一处提供，两边共用。

### 5. 时间窗按各指标自己的锚点

成片与视频耗时看完成时刻，每镜次数与一次通过看该镜首次出片时刻，运行看发起时刻，交付周期看最后成片时刻，模型用量整段对话按最后记账时刻归期。对话行的指标是这段对话的全量，时间窗只决定哪些对话入列。时段序列按调用方给的 IANA 时区切日 / 周 / 月，缺省 UTC；不然日报对新加坡团队差八小时。有界时间窗内每一期都出一行，没动静的期补零，前端画趋势不用自己补轴。

## 取舍

- **接受**：用量台账只有累计值，按时段看消耗只能把整段对话归到最后记账的那一期，切不开。这是 ADR-0026 选累加表的必然结果。
- **接受**：`slow`（周期超 P90）与 `spend`（token 超 P95）的门槛按当前筛选范围现算，范围小时门槛会抖；样本少于十段时这两种异常参考价值有限。
- **接受**：JSONB 路径表达式（`metadata->'shot'`、`request->>'user_name'`）没有索引。现在几百行无所谓；`generation_jobs` 到几十万行、审计页明显变慢时，再加 `(kind, finished_at)` 的部分索引，现在不加。
- **不做**：新表、新列、物化视图。所有数字都从现有事实表现算。
- **不做**：把旧的 12 条无镜号视频补进口径。它们在 `missing_shot` 异常里可见，不参与成功率。
