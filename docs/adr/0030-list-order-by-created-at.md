# ADR-0030：列表一律按建立时间倒序，审计时间窗同口径

- 状态：已接受（2026-09-17）
- 关联：[ADR-0021](0021-conversation-soft-delete.md)（软删与墓碑）、[ADR-0024](0024-audit-deleted-conversations.md)（审计游标索引收全部行）、[ADR-0027](0027-audit-reports.md)（报表时间窗按各指标自己的锚点）
- 修订合同 [§6 对话](../../contract/conventions.md#6-对话-conversations)、[§7 合集](../../contract/conventions.md#7-合集-collections)、[§8 创作需求单](../../contract/conventions.md#8-创作需求单-tasks)、[§12 审计报表](../../contract/conventions.md#12-审计报表-audit) 的排序与筛选描述；迁移 `0010_order_by_created_at`。

## 背景

侧栏两区、全部对话、标题搜索四个列表共用 `conversations.updated_at` 排序，而这一列在开跑、改名、改归属时刷新。于是顺序跟着操作抖：给一段对话发条消息，整列往下挪一格；SSE 事件触发重拉后顺序又可能换一次。需求单列表是同一个毛病，还多一层错位——卡片写着「添加于」某个建立时间，列表却按最后改动排，看上去像没排序。

排序键与「最后活动」这个事实绑在一起，是这些现象的同一个根因。

## 决策

### 1. 排序键统一为 `(created_at DESC, id DESC)`

覆盖侧栏任务区、合集内对话、合集列表、全部对话、标题搜索、需求单列表、需求单下的尝试，没有例外。`created_at` 写一次不再变，列表位置只随新建改变。`id` 只做同刻兜底：UUID 的大小没有业务含义，但游标翻页必须有唯一的第二排序键，否则同一时刻的两行会漏取或重复。

### 2. 需求单下的尝试也倒序

原来按 `created_at` 正序表达「第几次尝试」。改倒序后最后一次在上，与全站一致；序号语义仍按建立先后计算，只是展示方向反过来。该端点目前没有前端消费，改动实际只落在合同描述上。

### 3. 审计时间窗筛选跟随排序键

`since` / `until` 从 `updated_at` 移到 `created_at`，筛选与排序同列，一个索引同时支撑两者。代价是列表与同页报表不再是同一批对话：报表按各指标自己的事件锚点分桶（ADR-0027 决策 5），「最近 7 天」在报表里是这段时间发生的事，在列表里是这段时间建立的对话。合同与筛选控件的文案都写明按建立时间筛。

### 4. `updated_at` 退为「最后活动」事实，不再参与列表

没有列表按它排序、筛选或展示了。它仍由开跑、改名、改归属刷新，供异常报表的 `idle` 指标（最近活动距今超过 `idleHours`）使用，`ix_conversations_updated` 因此保留。

### 5. 游标携带排序键值

`PageCursor` 存的是排序键而不是某个具名时间列，编码、解码、续页条件三处同源。排序键换列时它们必须一起改，只改一处会静默漏条或重复。

## 取舍

- **接受**：正在跑的对话不再冒到列表顶部，找它只剩 `state=running` 这个入口。
- **接受**：把旧对话移入合集后按建立时间插队，可能不在合集首屏 10 条内，要展开才看得到。
- **接受**：上线瞬间在途的旧游标错位一次，刷新即恢复。游标不透明且短命，不做兼容。
- **不做**：改「什么时候刷新 `updated_at`」。它同时是搜索、审计筛选与 `idle` 指标的事实源，动它等于一次改三处语义。
- **不做**：侧栏与审计各用一套排序键。规则要能一句话说完，共用的分页实现也不必为此加「按哪列排」的开关。
