# ADR-0001：界面文字统一采用书面语规范

- **状态**：已接受（2026-10-09）
- **影响范围**：[前端实现规范](../../web/docs/frontend-implementation.md#界面文字)「界面文字」一节

## 背景

早期前端页面的提示词比较口语化，不同模块对同一类状态（如报错、禁用原因、空状态）的句式写法不一致，影响了专业感与阅读体验。

## 决策

前端界面上由本系统产生的所有文字（包含按钮、标题、状态提示、悬停说明和前端校验报错，后端接口返回的原始报错内容除外）统一遵循以下规范：

1. **使用规范书面语，禁用口语和语气词**：统一写「无法」「尚未」「查看」「该 / 本 / 此」，不写「不能」「还没」「看」「这条 / 这张」。
2. **不直接称呼用户**：文案中不出现「你」或「你的」。
3. **按钮和标题使用完整的动宾或名词短语**：例如写「采用最新版本」，不写「用最新的」。
4. **各类状态提示使用固定句式**：
   - **前置阻止**：「`<原因>`，无法 `<动作>`；请 `<下一步操作>`」
   - **操作失败**：「`<动作>` 失败，请 `<下一步操作>`」
   - **进行中**：「正在 `<动作>`」
   - **操作完成**：「已 `<动作>`」
   - **空状态**：「暂无 `<内容>`」
   - **操作引导**：「`<动作>` + 可 + `<结果>`」
5. **屏蔽技术内部标识**：面向用户的报错不出现英文单词、JSON 字段路径或 HTTP 状态码；展示后端返回的错误说明时，前面只加一层「`<动作>` 失败：」。
6. **标点与术语**：单句提示末尾不加句号；业务名词与 [CONTEXT.md](../CONTEXT.md) 保持一致。

## 取舍

- **接受**：界面整体语气偏正式、克制。
- **不做**：管理后台等内部页面同样遵守本规范，不放宽要求。
